# day08｜函数(方法)、参数、返回值、out输出参数、变量作用域、try‑catch异常处理、Debug调试知识总结

## 1、所学知识清单

### ① 上节回顾

- 类型转换、`Parse / TryParse`；数字/日期格式化
- `DateTime`时间、时间戳、`TimeSpan`时间差
- System.Text.Json序列化、反序列化
- 规整多维数组`int[,]`；交错数组`int[][]`

### ② 函数（方法）

> 函数：把重复业务代码封装打包；**定义不会执行，调用才执行**；实现代码复用、逻辑封装。

1. **具名函数（标准写法）**

- 无返回值：`void 函数名(形参){ }`
- 有返回值：`返回类型 函数名(形参){ return 值; }`
- `return`两个作用：①把结果返回给调用处；②**立刻结束当前函数，后面代码不再执行**。

1. 委托形式定义函数

- `Action`：代表**无返回值**函数；`Action<T>`带参数无返回。
- `Func<T1,T2,...TReturn>`：代表**带返回值**函数，最后一个泛型是返回值类型。
- lambda箭头写法：`(参数)=>{代码}`。

1. 参数

- **形参**：函数定义时小括号内的变量；**实参**：调用函数传入的实际数据。
- **可选参数（默认参数）**：`void Cal(int n1, int n2 = 10)`；带默认值参数放必选参数后面；调用不传实参就使用默认值。
- **命名参数**：调用时可以指定参数名，打乱顺序传参 `Cal(n2:20,n1:10,opt:"+")`。
- **out输出参数**：函数内部给out变量赋值，调用方拿到函数输出的额外结果；语法`bool Fn(string[] arr, out string res)`。

1. 函数案例

- 封装乘法表、质数判断、登录校验、价格折扣计算。

### ③ 变量作用域

- 变量作用域被**大括号{ }限制**。

- 内部大括号可以访问外部定义的变量；**外部不能访问大括号内部定义的变量**。

- 嵌套lambda/函数可以捕获外层局部变量；内部修改会真实改变外层变量值。

  > for、if、普通代码块`{}`里面定义的变量，出大括号直接失效。

### ④ 异常处理 try‑catch‑finally

1. 目的：捕获运行错误，**防止程序直接崩溃**，记录错误日志，释放资源。

```
try
{
    // 有可能报错的风险代码
}
catch(特定异常 ex)
{
    // 捕获对应类型异常，处理错误
}
finally
{
    // 无论是否发生异常，【一定执行】，用于释放资源：关闭文件、网络、数据库连接
}
```

1. 常用异常对象成员

- `ex.Message`：简短错误提示；
- `ex.StackTrace`：堆栈信息，定位报错代码行，调试排错。

1. 多catch：**子类异常写前面，基类Exception写最后**。
2. `finally`可以搭配try不带catch：异常继续向上抛出，但仍然执行资源释放。
3. 手动抛出异常 throw new 异常类型("提示")
   - 使用场景：参数合法性校验、业务规则不满足、未实现功能；
   - 常用异常类：`ArgumentException`参数非法、`InvalidOperationException`业务非法、`NotImplementedException`功能未实现。

> 常见系统异常：
>
> | 异常类型                   | 含义                             |
> | -------------------------- | -------------------------------- |
> | `FormatException`          | 格式转换失败（字符串转数字失败） |
> | `IndexOutOfRangeException` | 数组下标越界                     |
> | `DivideByZeroException`    | 除以零                           |
> | `NullReferenceException`   | 空引用，访问null对象成员         |

### ⑤ Debug调试快捷键

- F10：逐过程，一行行向下执行，不进入函数内部。

- F11：逐语句，进入函数方法内部跟踪执行。

- F5：继续执行，直接跑到下一个断点。

  > 使用前提：在代码行左侧点击设置断点。

## 2、易错点

1. 函数定义完**不会自动运行，必须调用才执行**。
2. `return`执行之后，函数后续全部代码不再执行。
3. 默认（可选）参数必须放在**必选参数的后面**，否则编译报错。
4. out参数：函数内部必须对out变量赋值，调用方才能使用。
5. 作用域：大括号内定义的变量，出`{}`就不能访问；不要在if/for内部定义需要外部使用的变量，要把变量定义在外层。
6. 多catch顺序：**具体异常放前面，基类Exception放最后**；如果把Exception写最前面，后面所有catch永远不会执行。
7. finally块无论报错、return，都会执行；适合资源释放，不要写业务逻辑。
8. 手动throw抛出异常，是业务校验；不是用来捕获错误；throw之后代码直接终止。
9. lambda捕获外部变量：嵌套函数修改外部局部变量，会真实改变外层变量的值，容易产生隐藏bug。

## 3、拓展（工业视觉上位机）

1. 上位机大量封装函数：串口发送接收、相机拍照、缺陷检测、PLC交互逻辑，每个功能封装函数，减少重复代码。
2. `out`参数：函数需要返回**多个结果**的时候使用，比如解析报文同时返回是否成功+解析出的数据。
3. try‑catch非常关键：串口、TCP通信、文件读写、解析MES报文都有可能出错，必须捕获异常，防止上位机直接闪退；finally关闭串口、网络流。
4. 手动throw：校验相机参数、检测参数合法性，参数非法直接抛异常，提前拦截错误业务数据。
5. Debug调试：排查相机拍照逻辑、报文解析bug，F10/F11断点调试是日常排错主要手段。

## 4、面试重点

1. void函数和带return返回值函数区别？return有哪两个作用？

   > void无返回值；带返回值函数可以把计算结果交给调用处继续处理；return一是返回结果，二是立刻结束函数，后面代码不再运行。

2. 形参和实参？什么是可选参数，书写有什么要求？out参数作用？

   > 形参函数定义的参数；实参调用传入的值；可选参数带默认值，必须写在必选参数之后；out用于函数输出额外多个结果。

3. C#变量作用域规则？

   > 变量受大括号{}约束；内部可以读外部变量；外部不能访问大括号内部定义变量。

4. try‑catch‑finally分别干什么？finally什么场景用？

   > try放风险代码；catch捕获异常处理错误；finally无论是否异常必定执行；用于释放文件、串口、数据库等资源。

5. 多catch捕获异常书写顺序，为什么？

   > 具体派生异常在前，基类Exception写最后；如果基类放前面，后面catch永远无法触发。

6. throw手动抛出异常使用场景？

   > 参数校验、业务规则校验、标记未实现功能；拦截非法数据，提前暴露业务错误。

7. Action和Func区别？

   > Action：无返回值，可以带参数；Func：带返回值，最后一个泛型参数代表返回类型。

> 工业视觉补充：
>
> - 上位机把拍照、报文解析、缺陷过滤封装函数；
> - 串口/TCP/文件IO全部需要try‑catch保护，防止程序崩溃；
> - out适合函数同时返回执行状态和解析数据；
> - 调试相机、PLC交互逻辑，大量使用断点F10/F11调试。
