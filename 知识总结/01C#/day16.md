# day16｜装箱&拆箱、partial分部类知识总结

## 1、所学知识清单

### ① 回顾：值类型、引用类型

| 分类     | 存储位置 | 常见类型                                 | 特点                       |
| -------- | -------- | ---------------------------------------- | -------------------------- |
| 值类型   | 栈内存   | `int`、double、bool、char、struct、enum  | 变量直接保存数据本身       |
| 引用类型 | 堆内存   | `string`、object、数组、List、Dictionary | 栈存地址，真正数据放在堆中 |

> ✨重点：**object是所有类型的基类（祖宗类型）**，任意类型数据都可以赋值给`object`变量。

### ② 装箱（封箱）

> 概念：**值类型 → object引用类型**；把栈上的值类型数据复制副本，放到堆内存，object变量保存堆地址。

```
int num = 20;
object obj = num; // 自动装箱
```

装箱执行步骤：

1. 在堆内存开辟新内存空间；
2. 将值类型数据**复制副本**存入堆；
3. object变量保存堆内存地址；
4. ⚠️原栈上变量不受影响，修改原值不会改变堆里面副本。

```
int num = 20;
object obj = num;
num = 99;
Console.WriteLine(num);  //99
Console.WriteLine(obj);  //20，副本互相独立
```

### ③ 拆箱（开箱）

> 概念：**object → 值类型**；取出堆中object包裹的数据，复制回栈的值类型变量。 ⚠️**拆箱必须强制转换，不会自动完成拆箱！**

```
object obj = 20;
int num2 = (int)obj; //强制拆箱
```

拆箱执行步骤：

1. 校验堆内部实际存储的类型，必须和目标类型完全匹配；
2. 类型匹配：复制数据到栈上变量；
3. 类型不匹配 → 抛出运行时异常`InvalidCastException`。

❌错误示例

```
object obj = 20;
int n = obj; // 编译报错，不会自动拆箱
object o = 40;
double d = (double)o; // 运行报错：堆存的是int，不能直接拆为double
```

> 💡性能提醒：频繁装箱拆箱会产生大量堆内存对象，带来GC压力，**尽量避免大量使用**，会降低程序运行效率。

### ④ partial 分部类

> 作用：**将同一个类拆分到多个不同cs代码文件**；编译阶段编译器自动合并为完整的一个类。

```
// Student1.cs
partial class Student
{
    public int Id { get; set; }
    public void ShowId(){}
}

// Student2.cs
partial class Student
{
    public string Name { get; set; }
    public void ShowName(){}
}
//调用：合并后当作一个类使用
Student stu = new Student();
stu.Id = 1001;
stu.Name = "张三";
```

#### 分部类使用规则

1. 各个文件的类：**命名空间必须相同、类名完全一致**；
2. 每一处都必须写`partial`关键字，缺少会编译报错；
3. 访问修饰符必须保持统一；
4. 不能出现重复的属性、方法；不能写完全一样的成员，会编译冲突。

## 2、易错点

1. 装箱是**复制副本**，不是移动数据；修改原始值类型变量，不会改变装箱之后堆里面的数据。
2. 拆箱**必须强制类型转换**，不存在自动拆箱；类型不匹配直接抛`InvalidCastException`运行异常。
3. 拆箱要求堆里面实际存储的类型和目标类型完全一致，int装箱不能直接强制转double。
4. partial分部类：多个文件的同类必须全部带上partial；类名、命名空间保持一致；禁止重复成员。
5. object可以接收任意数据，但频繁装箱拆箱有性能损耗，上位机循环里面尽量避开。

## 3、拓展（工业视觉上位机）

1. 旧版非泛型集合`ArrayList`全部基于object，存入值类型会大量装箱拆箱；**优先使用泛型List，可以避免装箱拆箱，性能更好**。
2. 分部类partial：WinForm/WPF窗体项目大量使用；窗体自动生成的代码放在另外一个cs文件，业务代码写自己的文件，互不干扰。

## 4、📝面试重点

**Q1：什么是装箱？什么是拆箱？😃**

> A： 装箱：**值类型转object引用类型**，栈数据复制副本到堆内存，object保存堆地址，自动完成。 拆箱：**object转回值类型**，必须手动强制转换；校验堆内实际类型，类型不匹配抛异常。

**Q2：装箱之后修改原来的值类型变量，装箱得到的object会跟着变吗？为什么？🤔**

> A：不会变❗。装箱是复制一份副本放到堆，原始栈变量和堆里面副本互相独立，修改原值不会影响堆副本。

**Q3：装箱拆箱有什么性能问题？开发怎么规避？⚠️**

> A：频繁装箱拆箱会在堆生成大量对象，增加GC垃圾回收压力，拖慢运行速度。 规避：优先用泛型集合`List<T>`、`Dictionary<TKey,TValue>`，尽量少用ArrayList、object做容器。

**Q4：partial分部类作用，使用有哪些规则？📂**

> A：把同一个类拆分多个cs文件，编译自动合并成一个完整类。 规则：全部文件类加partial；命名空间、类名一致；访问修饰符统一；不能有重复成员。

**Q5：什么场景会用到分部类？工业/桌面程序？**

> A：WPF、WinForm窗体项目；窗体自动生成布局代码在单独文件，我们写业务逻辑在另一个文件，互不干扰。

> 工业视觉补充：上位机尽量优先泛型，减少object带来装箱拆箱损耗；做WinForm视觉工具会见到partial分部类。
