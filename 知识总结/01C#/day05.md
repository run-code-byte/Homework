# day05｜数组多种定义、Dictionary完整API、List去重、冒泡排序、嵌套集合查询案例知识总结

## 1、所学知识清单

### ① 上节回顾

- 循环：`while` / `do‑while` / `for` / `foreach`
- 循环控制：`break`结束整个循环，`continue`跳过本次循环
- 循环嵌套：外层执行1次，内层完整跑完一轮

### ② 数组的5种定义方式

1. 先声明后赋值：`int[] arr1 = new int[5];`，int类型默认元素为0
2. 声明并初始化：`int[] arr2 = new int[4]{1,2,3,4};`
3. 省略长度：`int[] arr3 = new int[]{10,20,30};`
4. 简写老式语法：`int[] arr4 = {1,3,5,7};`
5. C#12新集合语法（中括号）：`int[] a = [1,2,3];`；`List<int> list = [10,20,30];`

> 数组：固定长度，`.Length`获取长度，下标从0开始，不能新增删除元素。

### ③ Dictionary字典完整API

```
Dictionary<键类型,值类型> dic = new Dictionary<键类型,值类型>(){};
```

| API                    | 功能说明                                                   |
| ---------------------- | ---------------------------------------------------------- |
| `Add(key,value)`       | 添加键值对；**key重复直接抛异常**                          |
| `ContainsKey(key)`     | 判断键是否存在，返回bool                                   |
| `ContainsValue(value)` | 判断值是否存在，返回bool                                   |
| `Remove(key)`          | 根据key删除，返回bool                                      |
| `Clear()`              | 清空全部键值对                                             |
| `Count`                | 属性，获取键值对总数量                                     |
| `Keys`                 | 获取全部键集合，可以`.ToList()`/`.ToArray()`转为集合、数组 |
| `Values`               | 获取全部值集合，可以`.ToList()`/`.ToArray()`转为集合、数组 |
| `TryAdd(key,value)`    | key不存在才添加；存在则添加失败，**不抛异常，返回bool**    |

字典三种遍历方式

1. 遍历整个键值对对象 `KeyValuePair`：`foreach(var item in dic){item.Key; item.Value;}`
2. 只遍历键：`foreach(var key in dic.Keys)`
3. 只遍历值：`foreach(var val in dic.Values)`

### ④ List集合去重4种手写思路

原始数据：`List<int> ints = [1, 3, 3, 3, 3, 4, 5, 6, 7, 7, 8, 6, 4, 2, 3];`

1. **双重循环删除**：外层取元素，内层对比后面所有元素；删除后执行`j--`修复下标塌陷。
2. **LastIndexOf**：判断元素第一次下标和最后一次下标是否一致，不一致删除末尾重复项。
3. **借助字典key唯一性**：把list元素作为字典key，再把Keys转回List。
4. **新建容器法**：新建空List，循环原集合，`!newList.Contains(item)`才Add。

> 重点：删除List元素，后续元素下标会前移，容易漏删。

### ⑤ 冒泡排序

- 原理：**相邻两个元素比较，不满足顺序就交换位置**；两层循环。
- 外层循环：控制比较轮次，最多执行`count‑1`轮。
- 内层循环：每一轮把最大元素“冒泡”到末尾，每轮比较次数递减`‑j`。
- 支持普通值类型排序，也支持嵌套集合`List<Dictionary<string,dynamic>>`，例如商品按价格、库存排序。

### ⑥ 嵌套集合业务案例

数据结构：`List<Dictionary<string,dynamic>>`，存储多条对象数据（歌手列表、歌曲列表、商品列表）。 业务逻辑：

1. 遍历A集合拿到关联ID；

2. 拿着ID遍历B集合匹配；

3. 匹配成功，把数据Add到结果List；

   > 案例：输入歌手名字，查询该歌手全部歌曲。 作业练习：按字段排序（price / stock，升序ASC、降序DSC）；通过歌曲反向查找歌手。

## 2、易错点

1. `dic.Add()`添加重复key直接运行报错；安全新增优先使用`TryAdd()`。
2. 直接使用`dic["不存在的key"]`取值，程序抛出异常；优先`ContainsKey`或者`TryGetValue`。
3. List循环删除元素，删除后下标塌陷，**忘记j--会漏删重复数据**。
4. 冒泡排序内层循环条件 `i < ints.Count‑1‑j`，忘记`‑j`，会重复对比已经排好序的末尾元素，虽然结果对但是性能差。
5. C#12 `[]`集合初始化语法，低版本VS不支持，老项目只能用`{}`。
6. 字典的`Keys`、`Values`本身不是List，不能直接用下标访问，必须调用`.ToList()`转换。
7. 嵌套字典集合排序时，取出的value是`dynamic`，比较大小语法允许，但字段名写错只会运行时报错，编译不会提示。

## 3、拓展

1. 实际项目不要手写冒泡排序，正式开发直接调用`list.Sort()`；手写冒泡主要用于面试笔试。
2. List去重正式项目可以用`Distinct()`；手写4种方法用于面试手写代码。
3. `List<Dictionary<string,dynamic>>`适合快速写demo；工业上位机正式项目建议定义实体class/model，编译期做类型检查，避免字段字符串拼写错误运行才发现bug。
4. 字典`.Keys.ToList()`会生成一份新List，修改新List不会改变原字典。
5. 关联查询模式（A表查ID，B表根据ID查数据）是上位机解析业务数据非常常见模式，比如缺陷集合、相机参数集合。

## 4、面试重点

1. Dictionary的Add和TryAdd的区别？

   > Add添加重复key抛异常；TryAdd key存在直接返回false，不会抛异常。

2. List循环删除元素会有什么坑？如何解决下标塌陷？

   > 删除元素后，后面元素下标前移，会跳过下一个元素；删除后`j--`回退下标。

3. 手写List去重有哪几种思路？（笔试常考）

   > ①双重for循环删除；②LastIndexOf判断；③字典key唯一性；④新建List+Contains判断。

4. 简述冒泡排序原理，两层循环各自作用？

   > 相邻两两比较交换；外层控制轮次，内层负责每一轮相邻元素对比，每一轮把最大值移动到末尾。

5. Dictionary有哪几种遍历方式？

   > 遍历KeyValuePair；遍历Keys；遍历Values。

6. `List<Dictionary<string,dynamic>>`优缺点？

   > 优点：快速构造复杂嵌套测试数据；缺点：字段是字符串，编译没有校验，写错字段运行时才报错，大型项目不推荐。

> 工业视觉岗位补充：
>
> 1. List存储缺陷检测结果，需要做去重、排序（按缺陷面积、坐标）；
> 2. Dictionary存储相机、光源、PLC设备配置参数；
> 3. 嵌套集合查询：根据产品编号查找全部检测记录、根据缺陷类型筛选结果。
