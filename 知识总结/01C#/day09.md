# day09｜委托、值类型&引用类型、ref/out/params、Lambda、元组、回调函数、List高级方法、文件IO知识总结

## 1、所学知识清单

### ① 上节回顾

- 函数封装、形参实参、可选/命名参数、`return`；
- 变量作用域（大括号`{}`约束）；
- try‑catch‑finally异常捕获、手动`throw`抛异常。

### ② 委托 Delegate

1. **委托概念**：类型安全的函数指针，用来保存、传递函数；把**方法当作数据**使用，实现行为参数化。
2. 自定义委托：`delegate 返回类型 委托名(参数列表);`，不能写在函数内部。
3. 系统内置泛型委托（日常优先用，不用手写delegate）
   - `Action` / `Action<T…>`：**无返回值**，可以带多个参数。
   - `Func<T…,TResult>`：**有返回值**，最后一个泛型是返回值类型。
4. **多播委托**：使用`+=`叠加多个方法；调用委托时，绑定的全部方法依次执行。

### ③ 值类型 & 引用类型（栈、堆内存）

> 栈Stack：速度快，存变量地址、临时值；堆Heap：存放对象真实数据。

1. 值类型

   ：

   ```
   int double bool char decimal struct
   ```

   - 变量直接存真实数据，存放栈上；
   - 赋值做**完整拷贝副本**；修改副本互不影响。

2. 引用类型

   ：

   ```
   string、数组、List、Dictionary、class自定义类
   ```

   - 栈中变量存**堆内存地址**，真正对象在堆；

   - 赋值仅拷贝地址，多个变量指向同一个堆对象；修改对象内容全部变量可见；

   - 重新赋值变量，变量指向新堆对象；旧对象等待GC回收。

     > ⚠️`string`是引用类型，但**字符串不可变**，任何修改都会生成新字符串对象。

### ④ 函数特殊参数

1. `params`可变参数
   - 语法：`方法(params T[] arr)`；只能放在参数列表**最后，只能一个params**。
   - 调用可以传入任意数量同类型实参，编译器自动封装成数组。
2. `ref`引用传递
   - 传递变量内存地址；方法内外操作**同一块内存**；
   - 调用前变量**必须初始化**；双向，既可以传入也可以传出；
   - 典型场景：交换两个变量；结构体大对象减少拷贝。
   - 引用类型参数不加ref：只能修改堆里面对象内容，不能让外部变量指向新对象；加ref可以修改外部变量的地址指向。
3. `out`输出参数
   - 专门用于**函数输出多个结果**；
   - 调用前可以不初始化；**函数内部必须给out参数赋值**；单向只输出；
4. ref vs out对比

| 特性         | ref              | out            |
| ------------ | ---------------- | -------------- |
| 调用前变量   | 必须初始化       | 可以不初始化   |
| 函数内部赋值 | 不强制可读可改   | 强制必须赋值   |
| 流向         | 双向：进+出      | 单向：只输出   |
| 用途         | 交换变量、结构体 | 函数多返回结果 |

> 注意：`Func/Action`泛型委托**不能使用ref/out参数**，这种场景必须写普通具名函数。

### ⑤ Lambda表达式（箭头函数）

- 本质：匿名委托的简写，`(参数)=>{方法体}`
- 简写规则
  1. 单个参数可以省略小括号；
  2. 方法体只有一行return逻辑，省略`{}`和`return`；
  3. 多行逻辑，大括号、return不能省略。

### ⑥ 元组 Tuple

- 轻量级复合数据，打包多个不同类型数据，不用定义class/struct。

1. 默认访问：`Item1、Item2…`；可以自定义元素名字。
2. **解构赋值**：`var (a,b,c) = 元组`；`_`下划线忽略不需要的成员。
3. 核心用途：
   - 函数返回多个返回值（替代out）；
   - 方法参数；
   - 集合存储简易结构化数据`List<(string name,int age)>`。

### ⑦ 回调函数

> 将一个函数作为另一个函数的参数传入，传入的函数就是回调函数；基于委托/func/action实现。

### ⑧ List高级方法（传入Lambda条件）

| 方法            | 作用                             | 返回值                         |
| --------------- | -------------------------------- | ------------------------------ |
| `Find`          | 找到**第一个**满足条件的元素     | 匹配元素，找不到返回默认值     |
| `FindLast`      | 找到**最后一个**满足条件的元素   | 匹配元素                       |
| `FindAll`       | 获取**全部**满足条件元素         | 返回新List                     |
| `FindIndex`     | 第一个匹配项下标                 | 找不到返回‑1                   |
| `FindLastIndex` | 最后一个匹配项下标               | 找不到返回‑1                   |
| `Exists`        | 是否**存在至少一个**满足条件元素 | bool                           |
| `TrueForAll`    | **全部元素**是否都满足条件       | bool                           |
| `ForEach`       | 遍历每个元素执行操作             | 无返回值void                   |
| `ConvertAll`    | 逐个转换每个元素生成新List       | 转换后的新List                 |
| `RemoveAll`     | 删除全部满足条件元素             | 返回被删除元素个数，修改原List |
| `Sort(lambda)`  | 自定义比较规则排序               | void，修改原集合               |

### ⑨ 文件&目录IO（`File` / `Directory` / `Path`）

> 需要引入命名空间 `using System.IO;`

1. File 文件操作

   - `File.ReadAllText(path)`：读取全部文本；
   - `File.WriteAllText(path,text)`：覆盖写入；
   - `File.AppendAllText(path,text)`：追加写入；
   - `File.Exists()` 判断文件是否存在；`File.Delete()`删除；`File.Copy()`复制；`File.Move()`移动/重命名。

2. Directory文件夹操作

   - `Directory.Exists()`判断文件夹；`CreateDirectory()`创建；`Delete()`删除；
   - `GetFiles()`获取目录下所有文件路径；`GetDirectories()`获取子文件夹；
   - `SearchOption.TopDirectoryOnly`只一级目录；`SearchOption.AllDirectories`递归全部子目录。

3. Path路径静态工具（

   不要手写斜杠，跨平台兼容

   ）

   - `Path.Combine()`拼接路径；
   - `GetFileName()`获取文件名；`GetExtension()`获取后缀；`GetDirectoryName()`获取目录。

## 2、易错点

1. 自定义`delegate`委托不能写在函数内部，只能命名空间或类里面。
2. 多播委托如果是Func带返回值，只会拿到**最后执行方法的返回值**。
3. 值类型、引用类型混淆：引用类型赋值只是拷贝地址；不加ref，函数内部new新对象不会改变外部变量指向。
4. `params`可变参数必须放在参数列表的**最后一位**，只能一个。
5. out参数函数内部**必须赋值**，否则编译报错。
6. Func、Action泛型委托不能使用ref/out参数，这种场景只能写普通具名函数。
7. Lambda简写：单行返回才可以省略`{}`和`return`；多行不能省略。
8. 元组单个元素：`(1,)`才是元组；`(1)`只是普通数字。解构用`_`占位忽略成员。
9. IO路径不要手动拼接斜杠`\ /`，统一使用`Path.Combine`适配操作系统。
10. IO操作极易发生异常：文件不存在、权限不足、占用锁；IO代码必须放在`try‑catch`；文件资源建议finally释放。

## 3、拓展（工业视觉上位机场景）

1. 委托/回调：相机采集完成回调、PLC报文接收回调；把处理逻辑当做回调传入。
2. ref：交换坐标点、结构体参数传递，减少拷贝；out老项目常见；新项目优先**元组返回多结果**替代out。
3. params：不定数量缺陷坐标、点位参数传入。
4. List高级方法：缺陷集合筛选`FindAll`过滤NG缺陷；`RemoveAll`删除无效检测点；`Sort`按缺陷面积/坐标排序；上位机业务高频。
5. IO文件操作：保存检测报告、图片路径管理、读写json配置文件、保存日志；`Path.Combine`拼接图片、配置路径。

## 4、面试重点

1. 什么是委托？Action和Func区别？多播委托是什么？

   > 委托是类型安全函数指针，存储/传递方法；Action无返回；Func有返回，最后泛型是返回值；多播委托`+=`绑定多个方法，调用全部执行。

2. 值类型与引用类型区别；string是引用类型有什么特殊？

   > 值类型栈存真实数据，赋值拷贝副本；引用类型栈存地址，堆存对象，赋值拷贝地址；string引用类型，但字符串不可变，修改生成新对象。

3. ref和out的区别？

   > ref调用变量必须初始化，双向可读可写；out调用可以不初始化，函数内部必须赋值，只用于输出多结果。

4. params参数使用注意事项？

   > params修饰数组，必须在参数列表末尾，只能一个；允许传入任意数量同类型实参。

5. Lambda表达式是什么，简写规则？

   > 匿名委托简写`()=>{}`；单参省小括号；单行return省大括号和return；多行不能省略。

6. 元组的作用，相比out有什么优势？解构`_`作用？

   > 轻量级打包多组数据；函数返回多个结果，替代out；`_`忽略不需要的元组成员。

7. List的Find、FindAll、Exists、TrueForAll区别？

   > Find取第一个匹配；FindAll返回全部匹配集合；Exists只要有一个满足true；TrueForAll全部满足才true。

8. IO中为什么推荐Path.Combine拼接路径？

   > 自动适配Windows/Linux路径分隔符，避免手动写`\ /`产生路径错误。

> 工业视觉补充：
>
> - 回调用于相机拍照完成事件；
> - List高级方法大量过滤缺陷、点位；
> - IO读写检测日志、配置、图片路径，注意加try‑catch捕获文件异常。
