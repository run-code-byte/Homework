# 图书管理系统项目总结（BookManager）

> 项目类型：控制台OOP综合实战，JSON文件持久化存储； 文件：`BookManager.cs`业务管理类、`Program.cs`程序入口；
>
>  特点：该版本使用`List<Dictionary<string,dynamic>>`做数据载体，**没有自定义实体Model类**。

## 1、项目整体架构

| 分层       | 作用                                                         | 文件           | 核心类                       |
| ---------- | ------------------------------------------------------------ | -------------- | ---------------------------- |
| 数据层     | 使用`Dictionary<string,dynamic>`存储单本图书数据，List承载全部图书集合，JSON持久化 | BookManager.cs | `Dictionary<string,dynamic>` |
| 业务管理层 | 封装增、删、改、查询全部、查询单本；封装JSON读写逻辑         | BookManager.cs | `BookManager`                |
| 交互入口层 | 控制台菜单，接收用户输入，参数简单校验，调用业务方法         | Program.cs     | `Program`                    |

### 业务功能清单

1. **新增图书**：输入书名、作者、标签、价格；正则校验价格格式；按书名判重；自动生成随机Id；写入`book.json`。
2. **删除图书**：输入书名，查找对应记录，找到则删除，写回JSON。
3. **编辑图书**：输入书名与新信息；按书名查找；修改字典内部字段，写回JSON。
4. **查询全部图书**：读取JSON，输出全部图书列表；无数据提示。
5. **查询单本图书**：输入书名，查询单条图书信息。

> 图书字典字段：`name`书名、`author`作者、`mark`标签、`price`价格、`id`随机编号、`isBorrow`是否被借阅。

## 2、核心知识点

1. **JSON持久化完整流程**

   ```
   File.Exists判断文件 → File.ReadAllText读文本 → JsonSerializer.Deserialize反序列化为List<Dictionary<string,dynamic>>
   →内存做增删改操作 → Serialize序列化 → File.WriteAllText覆盖写回磁盘
   ```

    JsonSerializerOptions配置：`WriteIndented`美化JSON；`AllowTrailingCommas`允许末尾逗号。

2. List集合高级方法

   - `Exists()`：判断是否存在满足条件元素，用于新增时书名判重。
   - `Find()`：查找第一条匹配字典对象；引用类型，修改Find得到的对象会直接修改原List集合内元素。
   - `FindIndex()`：获取匹配元素下标，配合`RemoveAt(index)`做删除。

3. **正则表达式校验**：校验数字价格，匹配正数/小数。

4. 引用类型特性：`Find()`拿到的是字典的**引用**，修改该字典内部键值，原集合List的数据同步变化，不需要重新Add。

5. 控制台架构：`while`循环菜单 + `switch`分支分发业务。

```
//新增图书，按书名判重
public string AddBook(Dictionary<string, dynamic> bookDic)
{
    List<Dictionary<string, dynamic>> bookList = new();
    if (File.Exists(path))
    {
        var json = File.ReadAllText(path);
        bookList = JsonSerializer.Deserialize<List<Dictionary<string, dynamic>>>(json);
        //判重：书名不能重复
        bool exist = bookList.Exists(item => item["name"].ToString() == bookDic["name"]);
        if (exist) return "该书籍已经存！！！";
    }
    bookList.Add(bookDic);
    string jsonStr = JsonSerializer.Serialize(bookList, JsonOpts);
    File.WriteAllText(path, jsonStr);
    return "新增数据成功!!!";
}

//编辑图书，字典引用直接修改
public string EditBook(Dictionary<string, dynamic> bookDic)
{
    if (!File.Exists(this.path)) return "暂时没有书籍，请先添加";
    string str = File.ReadAllText(this.path);
    List<Dictionary<string, dynamic>> list = JsonSerializer.Deserialize<List<Dictionary<string, dynamic>>>(str);
    Dictionary<string, dynamic> findBookDic = list.Find(item => item["name"].ToString() == bookDic["name"]);
    if (findBookDic == null) return "要修改的书籍不存在，请先添加";
    //修改引用对象，原list同步变化
    foreach (var item in bookDic)
    {
        findBookDic[item.Key] = bookDic[item.Key];
    }
    File.WriteAllText(this.path, JsonSerializer.Serialize(list,this.JsonOpts));
    return "编辑成功！！！";
}
```

## 5、业务流程

### ✅新增图书流程

1. 用户输入：书名、作者、标签、价格；正则校验价格格式。
2. 读取book.json反序列化为图书List；`Exists()`判断书名是否重复。
3. 组装`Dictionary<string,dynamic>`图书字典，生成随机id、`isBorrow=false`（未借阅）。
4. 添加到List，序列化写回json文件。

### ✅编辑图书流程

1. 用户输入要修改的书名、新的作者、标签、价格。
2. 读取json，反序列化得到List；`Find()`按书名查找图书字典。
3. 找不到返回提示；**找到直接修改字典对象（引用类型，原集合同步变更）**。
4. 序列化写回JSON。

### ✅删除图书流程

1. 用户输入待删除书名；读取json反序列化。
2. `FindIndex()`获取下标，下标=-1代表不存在。
3. `RemoveAt(index)`删除；写回JSON。

### ✅查询单本图书流程

1. 用户输入书名；读取json。
2. `Find()`查找对应字典；找不到返回空字典；找到返回字典给上层打印。

## 6、⚠️本项目现存问题（重点，面试口述）

1. ❗使用`Dictionary<string,dynamic>`存储数据：**编译期没有类型检查，字段拼写错误运行时才报错，维护差；工业项目优先自定义实体class Model**。
2. 异常处理缺失：文件IO、`ReadLine`、解析没有`try‑catch`，非法输入直接程序崩溃。
3. 只对价格做正则校验；书名、作者、标签没有做非空、空白校验。
4. 没有封装通用JSON读写工具方法；多处重复写读文件代码。
5. 尚未实现：借阅、还书业务功能（作业拓展点）。
6. id使用`Random.NextDouble()`随机小数，会出现id重复风险；推荐自增int Id。

## 7、📝面试问答（对话式✨）

**Q1：这个项目数据为什么用Dictionary<string,dynamic>，有什么缺点？😯**

> A：可以快速搭建demo，不用写实体类； 缺点：编译阶段不检查字段名字，写错字段程序运行的时候才报错；正式上位机项目推荐自定义实体Model类。

**Q2：Find拿到字典对象，修改字典里面的键值，原List集合的数据会变吗？为什么🤔**

> A：会变化❗。Dictionary是引用类型，Find返回的是集合内部字典对象的**内存引用**，修改这个字典，原List里面的对象同步修改，不需要再次Add。

**Q3：简述新增图书完整业务流程？**

> A：
>
> 1. 获取用户输入，正则校验价格；
> 2. 读取json文件，反序列化为图书List；
> 3. Exists判断书名是否重复，重复直接返回提示；
> 4. 组装Dictionary字典，加入List；
> 5. 序列化List，覆盖写回book.json✅。

**Q4：JSON持久化完整流程？📂**

> A：判断文件是否存在 → ReadAllText读取文本 → 反序列化为List集合 → 内存做增删改 → Serialize序列化 → WriteAllText写回磁盘。

**Q5：对比【图书管理系统（Dictionary版本）】和【车辆租还系统（自定义实体Model版本）】，哪个更适合真实项目？为什么？**

> A：车辆租还自定义实体Model版本更适合真实项目👍。 实体类编译做类型检查，字段拼写错误编译报错；dynamic字典只能运行时发现错误，后期维护成本高。

> 工业视觉拓展：小demo可以用Dictionary快速开发；正式项目一律自定义Model实体；IO读写配置文件同样这套JSON流程。
