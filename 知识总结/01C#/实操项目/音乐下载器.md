# 音乐下载器项目总结

> 项目定位：控制台异步HTTP网络实战，`HttpClient`网络请求 + JSON接口反序列化 + 文件IO下载二进制文件。 文件：`Program.cs`主程序入口；`resultClass.cs`JSON嵌套实体Model类。

## 1、项目整体架构

| 分层        | 作用                                                      | 文件           | 核心类                             |
| ----------- | --------------------------------------------------------- | -------------- | ---------------------------------- |
| Model实体层 | 对应API返回的嵌套JSON结构，用于反序列化                   | resultClass.cs | `Res`、`Result`、`Song`、`Artists` |
| 交互业务层  | 控制台交互、HTTP异步请求、解析接口数据、下载二进制MP3文件 | Program.cs     | Program Main异步入口               |

### 业务完整流程

1. 用户输入歌曲名称；
2. HttpClient拼接url，**异步GET请求搜索接口**拿到JSON字符串；
3. 将JSON字符串反序列化为嵌套实体对象；
4. 遍历结果，打印序号、歌手、歌曲ID展示给用户；
5. 用户输入序号，取出对应歌曲ID；
6. 拼接下载接口地址，异步请求获取MP3字节数组`byte[]`；
7. `File.WriteAllBytes()`把字节数组写入本地磁盘生成mp3文件。

## 2、核心知识点

1. **async / await异步编程**

- `Main`入口写成`static async Task Main()`；网络IO使用`await`等待异步方法，不会阻塞线程。
- `HttpClient.GetStringAsync()`：获取接口返回字符串；`GetByteArrayAsync()`获取二进制字节（图片、音频、文件）。

1. **HttpClient网络类**

   > ⚠️注意：不要循环/每次请求都new HttpClient，会耗尽系统TCP端口；建议全局复用同一个实例。

2. **JSON嵌套实体反序列化**

- 根据API返回JSON嵌套结构，手写一一对应的实体类；实体属性必须`public`，否则反序列化读不到。
- 嵌套关系：`Res`最外层 → `Result` → `List<Song>`歌曲集合 → `Song`内部包含`List<Artists>`歌手集合。

```
public class Res
{
    public Result result { get; set; }
}
public class Result
{
    public List<Song> songs { get; set; }
}
public class Song
{
    public long id { get; set; }
    public List<Artists> artists { get; set; }
}
public class Artists
{
    public string name { get; set; }
}
```

1. 字符串插值`$""`拼接请求URL、保存文件名。
2. 文件IO二进制写入：`File.WriteAllBytes(保存路径, byte[]字节数组)`，用于保存音频、图片。

### 核心代码片段

```
static async Task Main(string[] args)
{
    Console.WriteLine("---请输入歌曲名---");
    string songName = Console.ReadLine();
    // ❗生产建议全局只实例一次HttpClient，不要每次new
    var httpclient = new HttpClient();
    string url = $"http://music.163.com/api/search/get/web?s={songName}&type=1&limit=10";
    //异步get拿json字符串
    string json = await httpclient.GetStringAsync(url);
    //反序列化为嵌套实体
    var ress = JsonSerializer.Deserialize<Res>(json);
    List<Song> songsList = ress.result.songs;
    //打印搜索列表
    for (int i = 0; i < songsList.Count; i++)
    {
        var songSinger = songsList[i].artists[0].name;
        var songID = songsList[i].id;
        Console.WriteLine($"{i + 1} : {songSinger}  歌曲ID：{songID}");
    }
    Console.WriteLine("---请选择想要下载的歌手序号---");
    int index = int.Parse(Console.ReadLine()) - 1;
    long songId = songsList[index].id;
    string downloadUrl = $"https://music.3e0.cn/?server=netease&type=url&id={songId}";
    string artistName = songsList[index].artists[0].name;
    string saveFileName = $"{songName}-{artistName}.mp3";
    //下载拿到字节数组
    byte[] fileBytes = await httpclient.GetByteArrayAsync(downloadUrl);
    File.WriteAllBytes(saveFileName, fileBytes);
    Console.WriteLine($"下载成功！文件：{saveFileName}");
}
```

## 3、⚠️现存问题（面试口述重点）

1. ❗`HttpClient`每次运行都new实例；频繁创建会造成TCP端口耗尽，**应当做成全局静态单例复用对象**。
2. **缺少异常处理**：网络超时、接口404、用户输入非数字、JSON解析失败、磁盘写入异常没有`try‑catch`，程序直接崩溃。
3. 没有判空：搜索结果`songsList`为空，直接遍历会报错；取`artists[0]`，歌手数组为空会下标越界。
4. 用户输入序号没有做边界校验，输入超出列表范围，下标越界。
5. 文件名没有做特殊字符过滤，歌曲名包含`/ \ * : " < > |`等Windows非法文件名字符，保存文件会报错。
6. 没有配置请求头User‑Agent，部分接口会拦截默认HttpClient请求。

## 4、📝面试问答（对话式✨）

**Q1：HttpClient的GetStringAsync、GetByteArrayAsync分别用来干什么？😃**

> A： `GetStringAsync`：获取接口文本JSON字符串； `GetByteArrayAsync`获取二进制字节数据，适合下载图片、音频、小文件。

**Q2：HttpClient使用有什么重要注意事项？🤔**

> A：不要每次请求都new HttpClient；频繁实例会耗尽系统TCP端口；项目中尽量全局复用同一个HttpClient实例。

**Q3：为什么要写嵌套实体Res/Result/Song，直接用Dictionary<string,dynamic>不行吗？**

> A：Dictionary可以跑通demo，但是运行时才做类型检查；自定义实体类编译期检查字段，写错属性编译报错，可读性高，正式项目优先实体Model。

**Q4：async+await在这里起到什么作用？**

> A：网络IO是耗时操作，`await`等待网络请求完成，不会阻塞线程；控制台Main入口必须标记`async Task Main`才能使用await。

**Q5：下载MP3音频，拿到byte[]之后怎么存成本地文件？**

> A：`File.WriteAllBytes(文件路径,字节数组)`，把二进制字节直接写入磁盘文件。

> 工业视觉拓展：上位机经常HttpClient调用MES WebAPI，获取JSON；下载图片、二进制文件；同样async‑await防止UI卡死；定义实体Model接收接口返回JSON。
