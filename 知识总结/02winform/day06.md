## 1、上节回顾

1. 控件事件

- `SelectedIndexChanged`：下拉框选中改变；`SelectedIndex`下标、`SelectedItem`选中内容。
- `CheckStateChanged`：复选框三态变化；`CheckState`枚举：`Checked`选中 / `Unchecked`未选中 / `Indeterminate`半选；
- `CheckedChanged`只监听true/false二态切换。

1. 坐标转换：`PointToScreen`、`PointToClient`、`Point.Offset()`。
2. 窗体：`Show()`、`Hide()`、`Close()`、`Application.Exit()`；`Load / Shown / FormClosing / FormClosed / Resize`生命周期事件。
3. AntdUI：NuGet安装，美化WinForm原生控件。

## 2、用户控件 UserControl

### 作用

把项目中**多处重复使用的一组控件布局+业务逻辑封装成一个自定义控件**，减少重复写界面、重复写逻辑，提高复用性。

> 场景：新增/编辑图书表单、参数面板，多处界面需要使用，封装成UserControl。

### 使用步骤

1. 项目右键 → 添加 → **用户控件(Windows窗体)**，生成`.cs`用户控件文件；
2. 在设计器拖拽控件，完成布局，编写内部业务代码；
3. 解决方案右键【生成解决方案】编译项目；
4. 工具箱会出现自己写的用户控件，直接拖拽到窗体上使用。

> 本质：UserControl也是一种容器，和Form类似，只是没有标题栏，专门用来嵌入到窗体内部。

## 3、控件之间三种通信方式

### ① 父子通信（父窗体 → 子控件）

> 父实例化子控件对象，直接访问子控件公开属性、调用子控件公开方法，实现父向子传数据。

- 父持有子控件对象引用，直接赋值属性，调用方法。
- 简单直接，仅限于**父子嵌套关系**。

### ② 子控件 → 父控件（子父通信，自定义事件⭐重点）

实现：**子控件定义自定义事件，父窗体绑定该事件；子控件内部触发事件把数据回传给父**。

1. 在子UserControl内部声明自定义事件：

```
// BookInfo为实体类，事件携带回传的数据
internal event Action<BookInfo> OnSaveClick;
```

1. 子控件内部业务完成时，触发事件（`?.Invoke`空安全调用）

```
// 组装数据实体
BookInfo book = new BookInfo(...);
OnSaveClick?.Invoke(book); //触发事件，把数据传给父
```

1. 父窗体：实例化子控件，绑定自定义事件，在回调函数接收子控件传过来的数据做业务处理。

> ✨要点：子控件只负责触发事件，**不直接操作父窗体控件**，解耦，子控件可以复用到别的窗体。

### ③ 非父子通信：跨窗体、毫无嵌套关系的两个窗体/控件

> 没有父子嵌套，互相拿不到对方对象引用；采用**单例消息中间人（消息盒子）模式**。

#### 实现思路

1. 写一个消息管理类，做成**单例模式**，保证全局永远只有同一个实例。
2. 内部维护一个消息字典：key=唯一标识暗号Id，value=回调函数（Action）。
3. 接收方：向消息中间人注册，传入暗号Id + 自己用来接收数据的回调函数。
4. 发送方：调用中间人发送方法，传入暗号Id + 要传递的数据；中间人根据Id找到对应的回调，执行回调把数据给到接收方。

> 适用场景：两个完全独立窗体互相传数据，互相没有引用；上位机模块之间解耦通信。

## 4、易错点

1. 用户控件写完之后，**必须【生成解决方案】编译，工具箱才会出现该控件**，否则拖拽不了。
2. 子父通信：不要在子控件内部直接写父窗体的控件名字，强耦合；使用自定义事件向外抛数据。
3. 自定义事件调用优先使用`事件?.Invoke(参数)`，防止没有绑定事件的时候报空异常。
4. 单例消息中间人，保证全局唯一实例，不能每次new新对象，否则注册和发送不是同一个消息盒子，收不到消息。
5. 非父子消息模式要注意内存泄漏：窗体关闭时要注销注册的回调，避免对象无法被GC回收。

## 5、工业视觉上位机拓展

1. UserControl：封装重复的参数配置面板、相机参数面板、缺陷显示面板，多个TabPage、多个窗体直接复用。
2. 子父自定义事件：子参数面板修改参数，通过事件把参数抛给主窗体，主窗体执行硬件设置。
3. 单例消息中间人：不同独立子窗体之间传递检测结果、设备状态消息，模块解耦。

## 📝面试问答

**Q1：什么是UserControl用户控件，用来解决什么问题？😃**

> A：把一组重复的控件布局和业务逻辑封装成自定义控件。多处界面需要相同UI逻辑时复用，避免重复写界面代码。写完要生成解决方案，工具箱才会出现。

**Q2：子控件怎么把数据回传给父窗体？为什么不直接在子里面操作父的控件？🤔**

> A：子控件定义自定义`Action`事件；子控件内部`?.Invoke()`触发事件，把数据传出去；父窗体绑定事件接收数据。 如果子直接操作父控件，会产生强耦合，子控件就不能复用到别的窗体。

**Q3：两个没有父子嵌套关系的窗体，如何互相传递数据？**

> A：使用**单例消息中间人模式**；全局唯一的消息管理类，字典保存暗号和回调；接收方注册回调，发送方根据暗号推送数据。

**Q4：自定义事件为什么用 OnSaveClick?.Invoke(data)写法？**

> A：`?.`空安全判断，如果外部没有绑定任何事件，不会报空引用异常。

> 工业视觉补充：上位机大量使用UserControl封装参数面板；子模块通过自定义事件向上抛出状态、参数；跨窗体使用消息中间件做模块解耦。
