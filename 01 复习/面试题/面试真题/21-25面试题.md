1. 相机采集工件图像。
2. 使用定位工具找到工件特征，计算图像坐标系下工件位置与旋转角度。
3. 通过标定关系，把图像像素坐标转换为机械世界坐标。
4. 将偏移量、旋转角度下发给机器人/运动控制器，执行对位抓取。
5. 可选增加复检，确认动作完成后的位置状态。

3. CogCalibNPointToNPoint九点标定工具，完成像素坐标转世界坐标。
4. 几何工具FindLine/FindCircle辅助二次精定位。
5. 脚本工具计算坐标偏移，输出给上位机通讯下发。

4. 坐标仿射变换，标定后坐标转换计算。

## 23组

Q1：数据存储值类型和引用类型怎么选择？ A：

1. 小型、简单的数据，数据量小，生命周期短，优先选用值类型。
2. 数据结构复杂、体积大，需要跨方法共享、多地方同时修改同一个实例，优先使用引用类型。
3. 需要装箱拆箱频繁操作时，尽量避免值类型，减少性能损耗。

Q2：从数据库中取出一个数模型，怎么判断用class还是用结构体struct？ A：

1. 实体数据量大、需要多处共享实例，选class。
2. 数据很小，仅用来临时承载数据，不需要多实例共享，考虑struct。
3. 数据库映射实体一般**优先class**，ORM框架对class支持更好；struct是值类型，赋值会拷贝全量数据，实体大时开销高。

Q3：class和struct大小是有区别的，这个原因是什么？ A：

1. class是引用类型，实例分配在堆上，栈上只存引用地址（固定大小指针）。
2. struct是值类型，变量直接存储全部数据本身，占用内存等于所有成员内存总和。
3. class对象堆内还有对象头、类型指针等额外开销；struct没有对象头额外开销。

Q4：在一个项目中，大量使用引用类型，引用类型的对象也比较大，那么它会引发什么样的问题？ A：

1. 堆内存占用快速上涨，GC垃圾回收频繁触发，造成程序卡顿。
2. 内存碎片增多，大对象会进入LOH大对象堆，LOH默认不压缩，容易内存泄漏。
3. 大量对象创建销毁，增加GC压力，上位机UI、视觉算法线程出现延迟。

Q5：值类型和引用类型传的分别是什么？ A：

1. 值类型：传递的是**数据副本**，方法内修改副本不会影响原变量。
2. 引用类型：传递的是**对象引用（地址）**，方法内修改对象内部字段，会影响原始对象；但重新赋值引用不会改变外部对象。

Q6：class和struct有什么区别？ A：

1. class是引用类型，分配在堆；struct是值类型，默认分配在栈。
2. class支持继承；struct不能继承类，只能实现接口。
3. class可以有无参构造函数；struct默认自带无参构造，不能自定义无参构造。
4. class实例是引用传递；struct默认是值拷贝。

Q7：字符串是值类型还是引用类型？为什么？ A：

1. string是**引用类型**，存放在堆上。
2. 但是字符串具备不可变性，一旦创建就不能修改；每次修改字符串都会生成新字符串对象，行为上看起来类似值类型。

Q8：字符串的拼接有哪些方法？ A：

1. - 直接拼接，少量字符串使用。
2. string.Format 格式化拼接。
3. $字符串插值，可读性更好。
4. StringBuilder，大量循环拼接场景，减少内存开销。

Q9：怎么判断字符串是否相等？怎么判断一个list是否相等？ A：

1. 字符串：`==` 或者 `string.Equals()`；推荐Equals，可指定忽略大小写。
2. List：直接`==`只判断引用是否同一个对象；需要对比内部元素，要用循环遍历或者SequenceEqual对比每一项元素。

Q10：接口类和抽象类的区别？在什么时候使用接口类？在什么时候使用抽象类？ A：

1. 抽象类用abstract修饰，可以有字段、已实现方法、构造函数；接口interface默认不能有实例字段，方法默认无实现。
2. 一个类只能继承一个抽象类，但可以实现多个接口。
3. 抽象类：多个类有大量公共代码、公共属性，抽取公共基础逻辑时使用。
4. 接口：定义一组能力规范，不同类型无继承关系，但具备相同行为时使用。

Q11：什么是委托和事件？有了委托为什么还要用事件？ A：

1. 委托：是存储方法的类型，相当于方法指针，可以保存多个方法。
2. 事件：是委托的封装，对外只允许订阅+=、取消订阅-=。
3. 委托对外可以直接赋值覆盖，不安全；事件保护委托，外部不能直接重置委托实例，防止被恶意清空。

Q12：Event可以外部调用吗？ A：

1. 在定义事件的类内部，可以触发调用。
2. 在类外部，**不能直接调用事件**，外部只能订阅或者取消订阅。

Q13：try-catch-finally的执行顺序？在try和catch中分别使用return，它们的表现有什么不一样？ A：

1. 顺序：先执行try代码块 → 异常触发进入catch → **finally一定会执行**。
2. try里return：会先执行finally，再返回结果。
3. catch里return：捕获异常后执行finally，再执行return；finally仍不会跳过。
4. 只有环境强制退出等极端情况finally才不会执行。

Q14：泛型是什么？为什么要用泛型？ A：

1. 泛型：定义类、方法时不指定具体类型，使用时再传入类型参数。
2. 好处：类型安全，编译期检查类型；避免装箱拆箱，提升性能；一套代码复用，不用重复写多个不同类型版本。

Q15：数据库中分页怎么写？ A：

1. MySQL：`limit offset,pageSize`。
2. SQL Server：OFFSET ... FETCH NEXT。
3. Oracle：ROWNUM分页。
4. 注意：大偏移量分页，limit大offset性能差，推荐主键id分页。

Q16：数据库查询起来比较慢，有哪些办法可以优化和排查？怎么分析SQL语句哪里慢？ A：

1. 排查：使用执行计划explain查看SQL，看是否全表扫描、索引失效。
2. 优化：给查询字段建立合适索引；减少select *，只查需要字段；优化where条件，避免索引失效函数；减少子查询，合理分页。
3. 检查是否存在锁、连接表过多、数据量过大等问题。

## 25组

Q1：设备上料到检测，状态流转是怎么设计的？ A：

1. 采用状态机模式，状态包含：待机、上料到位、相机采图、算法检测、结果输出、下料、异常报警。
2. 传感器触发上料完成，切换到采图状态；采图完成进入检测；检测完成输出OK/NG信号给PLC，之后回到待机或下料状态；出现超时、传感器异常直接进入异常状态。
3. 所有状态切换加校验，防止状态乱跳，同时记录状态日志方便现场排查。

Q2：不同传感器怎么监听，你代码如何处理 A：

1. 传感器信号一般通过PLC IO或者采集卡接入上位机。
2. 采用独立后台线程持续轮询或者事件回调监听IO信号，不阻塞UI主线程。
3. 增加信号防抖逻辑，过滤瞬间抖动噪声；不同传感器做独立事件分发，触发对应业务回调。
4. 信号状态做缓存，做状态校验，避免重复触发多次执行检测逻辑。

Q3：WPF哪个项目用的？ A：

1. 在**多相机视觉检测上位机项目**使用WPF开发。
2. 项目负责界面、参数配置、图像实时显示、检测结果展示、和PLC通讯，采用MVVM架构实现界面与业务解耦。

Q4：开发有没有用AI A：

1. 有使用，分为两块。
2. 一是项目内深度学习缺陷检测，使用YOLO/U-Net模型识别不规则瑕疵；二是开发辅助，用AI辅助写代码、查bug，但是核心业务算法、架构都是自己编写调试。

Q5：对接几个品牌相机，怎么链接，你怎么设计 A：

1. 对接过康耐视、海康、巴斯勒。
2. 设计抽象相机接口ICamera，封装统一方法：打开相机、关闭、采图、设置参数、注册图像回调。
3. 不同品牌相机单独写类实现这个接口，上层业务代码不依赖具体SDK，切换相机只需要修改实例化对象，不需要改动业务代码。

Q6：海康SDK库对接，相机怎么设计对接 A：

1. 引用海康SDK，封装相机类，实现之前定义的ICamera接口。
2. 初始化SDK，枚举设备，登录相机，设置曝光、触发模式、硬触发参数。
3. 注册图像回调函数，相机采集图像后回调，把图像转为VisionPro图像格式给到算法模块。
4. 增加异常捕获、断线重连、资源释放逻辑，防止内存泄漏。

Q7：代码开发设计模式 A：

1. 工厂模式：相机实例创建，不同品牌相机统一创建入口。
2. 状态机模式：设备状态流转管理。
3. 观察者模式（委托事件）：传感器信号、检测结果通知UI更新。
4. 单例模式：日志、PLC通讯管理类，全局唯一实例。
5. MVVM属于架构模式，用于WPF项目界面解耦。
