**Q4：你怎么做的二次检测** A：项目中两种二次检测方案，对应不同场景：

1. **同工位单次复检**：单次检测结果处于临界阈值、或者检测到异常时，自动触发二次采图，重复检测流程，排除偶然的粉尘、振动、光线波动导致的误检。二次检测仍不合格才判定为不良，大幅降低误检率。
2. **下工位成品复检**：贴合、装配完成后，在下一个检测工位二次拍照，检测成品的贴装位置、装配精度，验证最终加工效果，同时反馈修正前工位的定位补偿值。 二次检测会适当放宽严格度，排除偶发干扰，同时保证致命缺陷零漏检。

**Q6：你为什么选的是同轴光，根据什么去选的** A：选择同轴光核心是依据**工件表面特性与检测目标**，以pin针检测、金属表面微缺陷检测为例：

3. 无阴影畸变：同轴光垂直照明，不会产生斜射阴影，适合精密尺寸测量、微小pin针的轮廓检测，保证测量精度。 简单总结：高反光、微小表面缺陷、高精度测量场景，优先选同轴光。

**Q10：我看你的项目里面有一个电路板的pin针的检测，pin针比较细小你是怎么做到把误差控制在0.01内的，你的判断依据是什么、怎么去做的检测，图像是怎么处理的** A：

精度控制方法

1. **硬件选型保障**：选用高分辨率相机+远心镜头，单像素精度控制在0.005mm以内，从硬件层面保留分辨率余量；配合同轴光照明，消除反光与阴影，保证边缘清晰。
2. **算法精度优化**：采用亚像素边缘提取算法，边缘精度达到1/10像素级，远高于整像素精度；多次测量取平均值，抑制随机误差。
3. **标定校准**：用高精度陶瓷标定板做标定，标定残差控制在0.003mm以内；定期校准基准平面，补偿温度漂移、机械松动带来的系统偏差。

判断依据

以pin针的**尺寸公差与形位公差**为判定依据：包括引脚直径、高度、圆度、共面度、位置度、针脚间距，对比客户给出的公差阈值，超差则判定为不良。

检测与图像处理流程

1. 3D线扫相机沿pin针轴向扫描，获取完整轮廓点云数据。
2. 点云预处理：去噪、平滑，拟合基准平面，作为高度零基准。
3. 提取每个pin针的顶部、根部截面轮廓，拟合计算直径、高度、圆心坐标。
4. 多pin针联合计算共面度、位置度、间距参数。
5. 所有参数和公差对比，输出最终判定结果。

**Q11：你说根据图像的里面的一个面积去判定，他的凹陷还有凸起在图像上的呈现是怎么样的** A：分2D和3D两种呈现：

1. 2D成像（同轴光垂直照明）
   - 凹陷：光线射入凹陷后发生漫反射，返回镜头的光量减少，在图像上呈现**暗斑/暗区域**，面积对应凹陷的投影面积，深度越深灰度越暗。
   - 凸起：凸起表面反射光线更强，返回镜头的光量更多，在图像上呈现**亮斑/亮区域**，面积对应凸起的投影面积，高度越高灰度越亮。
2. 3D成像
   - 直接输出每个点的高度值，凹陷对应负高度差，凸起对应正高度差；面积是缺陷的水平投影面积，同时可直接计算深度/高度、体积参数。
3. 判定逻辑：通过Blob分析提取对应灰度区域，计算面积、平均灰度、高度差，对比阈值判定是否为不合格缺陷。

**Q12：你们在做这个的时候有遇到什么问题吗** A：pin针检测项目中遇到过三个典型问题，都已解决：

1. **金属引脚反光过曝，边缘模糊**：导致尺寸测量误差大。解决：光源前端加装偏振片，相机镜头前搭配对应检偏器，抑制镜面反光；调整同轴光入射角度，配合局部灰度拉伸，提升边缘对比度。
2. **来料倾斜导致共面度测量误差**：工件放置倾斜，基准面拟合偏差。解决：增加工件整体平面拟合，做倾斜校正，将所有pin针坐标转换到基准平面下再计算共面度，消除工件放置倾斜的影响。
3. **微小毛刺误判**：正常生产的微小工艺毛刺被误判为缺陷。解决：增加缺陷长度、面积、高度的多维度筛选，设置合理的容差阈值，区分工艺允许毛刺与不良缺陷。

**Q13：现场的光是怎么样的，那个板的颜色偏暗你的打光是怎么做的，有进行补光的操作吗** A：针对暗背景、低反光工件，从硬件和软件两层优化，有对应的补光与增强方案：

1. 硬件打光优化
   - 提升光源功率，适当调大光源电流，增加入射光量；选用高亮度LED光源，保证足够的光强输出。
   - 调整光源入射角度，采用多方向低角度环形光组合照明，减少镜面反射，增加漫反射光量，提升暗表面的整体亮度。

Q5：可以说一下 C# 里面值类型和引用类型吗？ A：

- **值类型**：存储在栈上，变量保存的是**数据本身**。赋值时拷贝一份新数据。 包含：int、double、bool、char、enum、struct。

Q7：可以说一下 class、struct 还有 record 这三者的区别吗？ A：

- class：**引用类型**，分配在堆；支持继承；默认是引用相等。
- struct：**值类型**，分配在栈；不能继承类；默认是值拷贝。
- record：分`record class`（引用类型）、`record struct`（值类型）；核心是**值相等性**，自动生成相等比较，适合用来存储不可变数据模型。

Q9：class 和 struct、record 有什么区别？ A：

1. class：引用类型，堆内存，适合复杂对象，可继承。
2. struct：值类型，栈内存，轻量小数据，不支持类继承。
3. record：重点是**值比较**，适合DTO、模型，方便判断两个实例内容是否相同。

Q10：什么情况下会用 struct，什么情况下会用 class 呢？ A： ✅ struct：**数据量小（一般小于16字节）、轻量、不需要继承、不需要堆分配**，比如坐标、点、尺寸参数。 ✅ class：数据量大、需要继承、需要多态、生命周期较长，业务实体、服务类、管理器类都用class。

Q11：Struct 不可以吗？那所以它的区别在哪呢？ A：struct不是不能用，是适用场景有限。 struct是值类型，赋值会完整拷贝；如果结构体很大，拷贝会带来性能损耗。并且struct不支持类继承，没有无参构造函数自定义（旧版C#）。 class引用类型，传递只传地址，开销小，支持继承多态，适合复杂业务对象。

Q12：参数修饰符有用过哪些？（指方法参数修饰符，不是方法修饰符） A：用过 `ref`、`out`、`in`、`params`。

Q13：ref、out、in 他们有什么区别？什么情况下用 params？ A：

- ref：传入前变量**必须初始化**，方法内可读可改，按引用传递。
- out：传入前不用初始化，**方法内必须赋值**，用于方法返回多个结果。
- in：只读引用，不能修改参数，用来避免大结构体拷贝。
- params：用于**可变数量参数**，可以传0个或多个同类型参数，只能放在参数列表最后。

Q14：params 一般怎么使用，知道吗？ A：

```
public double Sum(params double[] nums)
{
    double total = 0;
    foreach(var n in nums) total += n;
    return total;
}
```

调用：`Sum(1,2,3)`；底层自动打包成数组。只能一个params，必须放在参数末尾。

Q15：可以说一下委托以及多播委托吗？包括事件这些。 A： 委托是**类型安全的方法包装器**，可以保存方法引用。 多播委托：一个委托可以绑定多个方法，调用时依次执行所有绑定的方法，用`+`、`-`增加/移除方法。 事件是**委托的封装**，对外只提供订阅`+=`、取消订阅`-=`，限制外部直接赋值，更安全，防止外部清空所有订阅。

Q16：如果写在接口里面写一个事件，它为啥不行呢？ A：**接口里可以定义事件**，是允许的。 接口只定义事件的契约（订阅/取消订阅），不实现。实现该接口的class必须实现这个事件。 容易混淆的点：接口不能实现事件的具体后台字段。

Q17：创建线程有哪些方式？ A：

1. new Thread() 手动创建线程
2. ThreadPool 线程池
3. Task / Task.Run（推荐）
4. BackgroundWorker（旧WinForm）
5. 异步委托 BeginInvoke

Q18：Thread 和 Task 有什么区别？什么情况下会用 Thread 线程？ A： Thread：操作系统原生线程，创建销毁开销大，需要手动管理。适合**长时间常驻后台任务**，比如相机采集线程、串口监听线程，需要长期运行、可控启停。 Task：基于线程池，轻量，自动复用线程，支持async/await，适合短任务、IO、算法处理。

Q19：Task 如何被取消？ A：使用`CancellationTokenSource + CancellationToken`。

1. 实例化CTS，拿到Token传给Task。
2. 任务内部循环检测`token.IsCancellationRequested`，或者调用`token.ThrowIfCancellationRequested()`抛出取消异常。
3. 外部调用`cts.Cancel()`触发取消。

Q20：怎么把 Task 拉到主线程？你能把它拉到主线程吗？ A：不能把Task“迁移”到主线程。 Task执行在工作线程；如果需要在主线程执行UI操作，在`await`之后，**会自动回到调用时的同步上下文（WPF/WinForm主线程）**。 如果是后台线程，需要通过`Dispatcher.Invoke(WPF)`或者`Control.Invoke(WinForm)`切回UI线程。

Q21：哪些情况可以使用 Invoke？ A：后台线程需要**修改UI控件**的时候。UI控件只能由创建它的主线程访问，跨线程操作UI必须用Invoke。

Q22：如何确定当前是主线程？ A： WinForm：`control.InvokeRequired`，true代表不是主线程。 WPF：`Dispatcher.CheckAccess()`，返回true就是主线程。

Q23：Action 和 Func 的区别呢？ A：

- Action：无返回值的委托。`Action`、`Action<T1,T2>`。
- Func：**带返回值**的委托。最后一个泛型参数是返回类型。

Q24：还有其他的情况可以使用 Invoke 的吗？ A：除UI更新外，也可以用来**同步执行委托**；但绝大多数场景都是跨线程更新UI。

> 注意：委托本身的Invoke是同步执行，和控件的Invoke不是一回事。

Q25：说一下 Invoke、BeginInvoke、EndInvoke 这三者的区别？ A：

1. **Control.Invoke**：同步，后台线程提交委托到UI消息队列，**阻塞等待执行完成**才返回。
2. **Control.BeginInvoke**：异步提交，不阻塞当前线程，直接返回。
3. EndInvoke：搭配BeginInvoke获取返回结果，现在WPF/WinForm项目很少手写。

> 区分：委托的Invoke/BeginInvoke 和 控件的Invoke/BeginInvoke不是同一个东西。

Q26：知道 Invoke 底层的原理吗？ A：UI主线程维护消息循环。 后台线程调用Control.Invoke，内部把委托打包成消息，投递到UI线程的消息队列；UI主线程循环读取消息，执行委托。 Invoke会阻塞调用线程，直到消息处理完毕。

Q27：说一下线程安全。 A：多线程同时读写**共享资源（变量、集合、文件、数据库）**时，保证数据不会错乱、脏读、异常，就是线程安全。 如果多个线程只读不写，天然安全；只要存在写操作，就要做同步保护。

Q28：C# 里面内置的锁有哪些？哪些是悲观锁？哪些是乐观锁？ A： 悲观锁：`lock`（底层Monitor）、`Monitor`、`SemaphoreSlim`、`ReaderWriterLockSlim`。假设一定会发生竞争，访问资源先上锁。 乐观锁：`Interlocked`原子操作，无锁，假设冲突很少，发生冲突重试。 线程安全集合Concurrent系列底层混合实现。

Q29：lock 里面能放 async/await 异步代码吗？为啥不能？ A：**不建议，会有问题**。 lock是基于Monitor，Monitor是线程绑定的。await会释放当前线程，等恢复后可能是另一个线程，锁释放和获取不在同一个线程，锁会失效，造成死锁或者锁穿透。

Q30：如果必须要调用异步接口，lock里面放异步代码要如何解决？ A：使用`SemaphoreSlim.WaitAsync()`，支持异步等待，替代lock。

```
await semaphore.WaitAsync();
try
{
    await SomeAsyncFunc();
}
finally
{
    semaphore.Release();
}
```

Q31：SemaphoreSlim 和 lock 有什么区别？ A： lock：互斥锁，同一时间只允许1个线程进入；基于Monitor，不支持async等待。 SemaphoreSlim：信号量，可以设置允许N个线程同时进入；支持`WaitAsync`异步等待，适合异步场景。

Q32：线程安全单例，你写过吗？可以说一下怎么设计吗？ A：写过双重检查锁(DCL)单例。

```
public class Singleton
{
    private static volatile Singleton _instance;
    private static readonly object _lock = new object();
    private Singleton(){}
    public static Singleton Instance
    {
        get
        {
            if(_instance == null)
            {
                lock(_lock)
                {
                    if(_instance == null)
                        _instance = new Singleton();
                }
            }
            return _instance;
        }
    }
}
```

volatile防止指令重排；.NET Core也可以用Lazy更简洁。

Q33：什么是死锁？什么样情况下会导致死锁？ A：两个或多个线程，各自持有对方需要的锁，同时互相等待对方释放锁，**所有线程永久阻塞**，程序卡死。 四个必要条件：互斥、持有并等待、不可剥夺、循环等待。 典型场景：线程1持有A锁等B锁；线程2持有B锁等A锁。

Q34：Task 如何被取消？（再次追问） A：依靠`CancellationTokenSource`。

1. 创建CTS，拿到Token传入Task。
2. 任务内部循环检查`token.IsCancellationRequested`，或者调用`token.ThrowIfCancellationRequested()`抛出取消异常。
3. 外部调用`cts.Cancel()`发出取消信号。 取消是**协作式**，不是强制杀死线程，任务内部要主动检测。

Q35：GC垃圾回收，说一下它的原理。 A：CLR GC负责回收托管堆上不再被引用的对象。

1. 标记：从根对象（静态变量、栈变量）遍历，标记所有可达对象。
2. 清除：未标记的对象判定为垃圾。
3. 压缩：移动存活对象，消除内存碎片，更新对象引用地址。 分代回收：0代、1代、2代。新对象放0代，频繁回收；存活对象晋升到更高代。

Q36：如何去控制 GC？ A：

1. 减少临时对象，减少装箱，避免高频new小对象。
2. 大对象复用内存池，图像buffer复用。
3. 手动调用`GC.Collect()`（尽量少用，只在特定场景）。
4. 使用`WeakReference`弱引用。
5. 及时释放非托管资源，实现IDisposable。

Q37：托管资源和非托管资源？ A：

- 托管资源：CLR GC管理，堆上C#对象，GC自动回收。
- 非托管资源：操作系统资源，GC无法自动释放，比如文件句柄、相机句柄、串口、数据库连接、内存映射。

Q38：非托管资源手动如何释放？ A：实现`IDisposable`接口，在Dispose方法里释放句柄、关闭连接。使用`using`语句，自动调用Dispose。

Q39：如果 Dispose 释放不掉，那如何做呢？ A：

1. 检查资源是否被其他地方持有、未释放。
2. 终止相关线程，停止正在使用资源的任务。
3. 用终结器（~类名）兜底释放，作为最后保障。
4. 记录日志，异常上报，必要时重启模块/进程。

Q58：TCP三次握手和四次挥手？如何建立连接、如何断开？ A： **三次握手（建立连接）**

1. 客户端发SYN请求连接。
2. 服务端回复SYN+ACK，同意连接。
3. 客户端回复ACK，连接建立。

**四次挥手（断开）**

1. 客户端发FIN，告诉服务端我不再发数据。
2. 服务端ACK确认。
3. 服务端数据发完后，发FIN。
4. 客户端ACK确认，连接关闭。

Q2：了解异步与多线程的区别吗 A：多线程是**操作系统层面，并行执行多条执行流**，靠CPU多核实现并行，多个线程可以同时跑代码，会占用独立线程资源。 异步是**编程模型，重点处理IO等待场景**（读写文件、网络通讯），等待期间释放当前线程，线程可以去做别的事情，不需要一直阻塞等待。 简单总结：多线程解决**CPU密集型并行计算**；异步解决**IO等待，提高线程利用率**。异步不一定新开线程。

Q3：你是否了解gc是如何释放内存的 A：GC是CLR垃圾回收器，只负责托管堆内存。 核心流程：标记、清除、压缩。

1. 标记：从根对象（栈变量、静态变量）遍历，标记所有仍被引用的存活对象。
2. 清除：没有标记的对象判定为垃圾，标记对应的内存空间为空闲。
3. 压缩：移动存活对象，消除内存碎片，更新对象引用地址。 采用分代回收：0代、1代、2代，新对象放入0代，0代回收频率最高，存活对象逐步晋升到更高代。GC不是实时回收，是触发条件满足时自动执行。

Q4：什么是堆上的内存，什么是栈上的内存 A： 栈内存：由系统自动分配、自动释放，存放值类型、局部变量、函数调用栈帧。内存空间小，分配速度快，先进后出。方法执行完毕，栈内存自动回收。 堆内存：手动管理（托管堆由GC管理），存放引用类型对象实例，空间大。对象创建时分配，GC判断无引用后回收，生命周期不受方法限制。

Q5：什么是非托管内存与托管内存，有没有了解一些调内存的工具 A： 托管内存：CLR托管堆，C#中new出来的class对象，由GC自动管理。 非托管内存：操作系统原生内存，GC无法识别，例如相机缓存、文件句柄、串口资源，需要手动释放。 内存调试工具：Visual Studio内存诊断、dotMemory、PerfView，用来查看内存快照，定位内存泄漏、大对象。

Q6：如果两台高帧率相机在你的视觉软件里同时运行，出现卡死，怎么处理？（多线程无法解决） A：多线程无效，优先排查资源冲突、驱动、硬件、图像内存问题：

1. 检查网卡：双相机同时采集，确认是双独立网卡，避免单网卡带宽瓶颈，更换千兆/万兆工业网卡。
2. 相机驱动与SDK版本：两台相机SDK冲突，统一SDK版本，更新官方稳定驱动。
3. 图像内存：图像buffer复用，禁止频繁创建大图像对象，防止大对象堆碎片。
4. 资源抢占：检查工控机CPU、内存、PCIe带宽，确认硬件资源不足。
5. 锁冲突排查：全局锁阻塞采集流程，拆分共享资源，缩小锁范围。
6. 相机硬件层面：相机触发时序冲突，调整硬件触发信号，错开两台相机曝光采集时序。

Q7：modbus tcp 与rtu有什么区别 A： Modbus RTU：跑在串口RS485，二进制格式，带CRC校验；适合短距离低速设备。 Modbus TCP：跑在以太网TCP/IP，自带IP头，使用MBAP报文头，**不需要CRC校验**；传输速度更快，支持远距离，工业产线主流。

Q9：你有自己做过modbus数据包吗 A：有。可以手动组装Modbus TCP/RTU报文。 RTU需要计算CRC校验；TCP只需要组装MBAP头+功能码+数据，不需要CRC。调试阶段会手动构造报文，配合串口助手、wireshark抓包验证。

Q16：你了解九点标定的数学原理吗？你如何验证仿射矩阵是可靠的

 A：九点标定本质是**二维仿射变换**，建立像素坐标到世界机械坐标的映射关系，公式：Xw = a*Xp + b*Yp + c；Yw = d*Xp + e*Yp + f。 验证仿射矩阵可靠性：

1. 取标定板上多个不在标定点位的验证点，采集像素坐标，用矩阵换算成世界坐标。
2. 和实际机械坐标对比，计算残差误差。残差越小，矩阵越可靠；一般要求残差小于项目精度要求。
3. 也可以移动标定板，再次采点复测，验证重复稳定性。
