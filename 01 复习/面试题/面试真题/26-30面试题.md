Q7：描述你设计的多线程结构 A：

1. UI主线程：只负责界面刷新，不做算法、采图。
2. 图像采集线程：独立线程持续监听触发，采集图像送入图像队列。
3. 算法处理线程池：从队列取图执行视觉检测，多图并行处理。
4. 通讯/日志后台线程：独立线程处理PLC交互、日志保存，不占用算法线程。

Q8：相机共享图像队列，怎么确保线程安全 A：

1. 使用线程安全队列，或者在入队、出队操作加lock锁。
2. 图像对象采用内存池管理，避免多线程同时修改同一张图像。
3. 入队出队加状态判断，加异常捕获，防止队列读写冲突。

Q9：一些图像数据量大，需要频繁申请释放内存，怎么优化？ A：

1. 建立图像内存池，预先一次性申请多块图像内存，复用内存，避免频繁new和释放。
2. 图像使用完成后不直接销毁，放回内存池；减少GC频繁回收大对象，降低GC卡顿。
3. 及时释放非托管资源，使用using语句，防止内存泄漏。

## 27组

Q1：集合和数组有什么区别 A：

1. 数组长度固定，声明时确定大小；集合（List等）长度动态可变，可以随时增删元素。
2. 数组支持多维；普通集合多为一维。
3. 数组访问速度更快；集合封装了增删、查找等丰富方法，开发更方便。
4. 数组可以存值类型、引用类型；早期非泛型集合存在装箱拆箱问题。

Q2：集合与泛型集合 A：

1. 普通集合（如ArrayList）是非泛型，存储object类型，存入值类型会发生装箱，取出要拆箱，存在类型不安全问题。
2. 泛型集合（List、Dictionary<TKey,TValue>），定义时指定存储类型，编译期类型检查，无装箱拆箱，性能更高、类型安全。
3. 泛型集合是项目开发首选。

Q3：委托和事件 A：

1. 委托：是一种可以保存一个或多个方法的类型，相当于方法指针，可以直接赋值、调用。
2. 事件：是委托的包装，对外只允许订阅+=、取消订阅-=，外部不能直接赋值覆盖，提升安全性。
3. 事件本质是为了限制委托的访问权限，防止外部代码清空委托链。

Q4：GRR是什么 A：

1. GRR即测量系统分析里的**量具重复性与再现性**。
2. 用来评估视觉测量系统的稳定性，判断设备本身的测量波动是否满足检测要求。
3. GRR数值越小，代表测量系统越稳定可靠。

Q5：构造函数 A：

1. 构造函数是创建类实例时自动调用的特殊方法，函数名和类名相同，没有返回值。
2. 作用：初始化对象的字段、属性，给对象赋初始值。
3. 可以重载，编写多个不同参数的构造函数；struct自带默认无参构造。

Q6：什么是序列化 A：

1. 序列化：把对象在内存中的实例，转换成可存储/传输的格式（JSON、二进制、XML）。
2. 反序列化：把存储的文本/二进制数据，还原成内存对象。
3. 项目用途：保存视觉参数配置、上位机配置文件，方便加载保存。

Q7：多线程的含义 A：

1. 一个进程内可以同时开启多个独立执行的线程，CPU快速切换执行。
2. 可以并行执行多个任务，例如一边采图、一边跑算法、一边更新UI，避免单线程阻塞卡顿。
3. 多线程要处理线程安全、资源竞争问题。

Q8：类跟结构体 A：

1. class是引用类型，分配在堆上；struct是值类型，默认分配在栈。
2. class支持继承；struct不能继承类，仅能实现接口。
3. class创建实例时new；struct可以不用new直接声明。
4. class赋值传递引用；struct赋值会拷贝完整数据副本。

Q9：视觉引导的流程 A：

1. 相机采集工件图像。
2. 使用定位工具提取工件特征，得到图像坐标系下的位置与角度。
3. 通过九点标定，将像素坐标转换为机械世界坐标。
4. 计算工件相对基准的偏移量、旋转角度。
5. 将坐标偏差下发给机器人/运动控制器，执行抓取、对位动作。
6. 可选增加复检，校验动作完成后的位置。

## 28组

Q1：九点标定的逻辑 A：

1. 在运动平台上移动标定板，采集9个不同位置标定点的图像像素坐标，同时记录对应的机械世界坐标。
2. 通过两组坐标求解仿射变换矩阵，建立像素坐标到机械坐标的映射关系。
3. 后续视觉算出工件像素坐标，代入矩阵，直接换算成运动机构可用的世界坐标。

Q2：十二点标定与九点标定是区别 A：

1. 本质都是多点仿射标定，**九点是行业最常用标准方案**，采集9组坐标求解变换矩阵。
2. 十二点标定采集12组坐标，采集样本更多，对畸变、安装倾斜拟合效果更好，标定残差通常更低。
3. 九点满足大部分2D引导场景；十二点多用于精度要求更高、镜头畸变偏大、视场较大的场景，缺点是采集点位更多，现场标定耗时更长。

Q3：视觉引导的流程 A：

1. 相机采集工件图像。
2. 定位工具识别工件特征，输出图像坐标系下工件位置与旋转角度。
3. 利用标定得到的坐标变换矩阵，把像素坐标转换成机械世界坐标。
4. 计算工件相对基准的偏移量、旋转偏差。
5. 通过通讯将偏移数据下发PLC/机器人，执行对位抓取。
6. 可选增加复检步骤，确认执行后的位置状态。

Q4：线扫相机的工作原理 A：

1. 线扫相机单次只拍摄一行像素（一条线）。
2. 依靠工件与相机之间的相对运动，连续采集一行行图像，拼接成完整二维大图。
3. 适合宽幅、大幅面连续产品检测，如卷材、板材、长工件表面缺陷检测。

Q5：blob软阈值与硬阈值有什么区别 A：

1. 硬阈值：设置固定灰度阈值，像素大于阈值直接归为前景，小于则为背景，只有二分类，边界生硬。
2. 软阈值：设置上下两个阈值区间，区间内像素做灰度权重过渡，保留部分灰度信息，抗噪声更好，适合边缘模糊的缺陷。

Q6：俯视机位和仰视机位 A：

1. 俯视机位：相机在工件上方，从上往下拍摄，最常用，适合工件上表面缺陷、顶部定位。
2. 仰视机位：相机在工件下方，从下往上拍摄，多用于检测工件底面、底部孔洞、底部划痕，需要注意工件透光、遮挡问题。

Q7：PLC有哪些通讯协议 A：

1. 以太网类：Modbus-TCP、S7协议(西门子)、EtherNet/IP、Profinet。
2. 串口类：Modbus-RTU、RS232、RS485。
3. 高速现场总线：EtherCAT，多用于运动控制、高速同步场景。

## 29组

Q1：对于C#语言，面向对象的设计方法和设计原则是什么？ A：

1. 设计方法：通过封装、继承、多态，把业务抽象成类与对象；将属性、行为封装在类内部，降低耦合，复用代码。
2. 核心原则为SOLID原则：单一职责、开闭原则、里氏替换、接口隔离、依赖倒置。
3. 单一职责：一个类只负责一件事；开闭原则：对扩展开放，对修改关闭。

Q2：工厂方法，简单工厂方法，抽象工厂方法分别是什么？ A：

1. 简单工厂：一个工厂类，根据参数，创建不同产品对象；缺点：新增产品需要修改工厂代码，违反开闭原则。
2. 工厂方法：定义工厂抽象接口，每个产品对应一个独立工厂类；新增产品只需要新增工厂类，不修改原有代码。
3. 抽象工厂：用来创建**一组相关系列产品**，一个工厂可以生成多种配套对象，适合成套产品创建场景。

Q3：程序里面需要一个全局变量，每个地方都可以用的，要怎么声明变量？ A：

1. 优先使用**静态类的静态属性**来实现全局数据，不推荐直接用public静态字段。
2. 如果是多线程访问，需要加锁保证线程安全；
3. 尽量控制全局变量数量，全局状态过多容易造成代码耦合、难以调试。

Q4：日志部分怎么处理是写了一个日志系统，系统怎么写的？ A：

1. 封装独立日志静态类，提供统一WriteLog接口，外部直接调用。
2. 日志内容包含：时间、日志等级、线程号、消息内容、异常堆栈。
3. 内部使用队列+独立后台线程，业务调用只写入队列，由后台线程统一落地保存，不阻塞主业务。
4. 支持按日期分割日志文件，限制单个文件大小，防止日志文件过大。

Q5：一条消息要记录是直接写到后台记事本里，假设两条消息同时存进记事本如何解决并发冲突？ A：

1. 方案一：写文件代码块加lock锁，同一时刻只允许一个线程执行文件写入。
2. 方案二：使用消息队列，所有线程把日志消息推入队列，**单个后台线程串行写文件**，从根源避免多线程同时写文件冲突，项目里优先选用这个方案。

Q6：日志丢失怎么处理？ A：

1. 使用队列缓存日志，程序正常退出时等待队列全部写完再释放资源。
2. 捕获写文件异常，写入备用缓存（内存缓冲区），重试写入；异常时把未写入日志备份。
3. 增加日志写入成功标记，记录写入状态；程序崩溃场景可以增加兜底保存。
4. 限制队列最大长度，防止内存暴涨，队列满时做告警。

Q7：要看某一类的日志反向查询怎么做？ A：

1. 日志保存时，每条日志带上标签、日志等级、模块名称。
2. 查询时读取日志文件，按关键词、时间范围、日志等级、模块字段进行过滤检索。
3. 量大时可以简单索引，把日志按时间分文件，查询只加载对应时间段文件，减少读取开销。

Q8：日志分什么等级？ A：

1. Debug：调试信息，开发阶段使用，现场发布一般关闭。
2. Info：正常运行信息，记录流程、状态变化。
3. Warn：警告，不中断程序，但存在潜在异常。
4. Error：错误，业务逻辑异常，任务失败，但程序还可以继续运行。
5. Fatal：致命错误，程序可能直接崩溃。

Q9：把日志内容展示到窗口上创建一个表格，如果有十个线程同时展示，显示跟后台记录怎么一一对应，显示上不会少不会乱，保存上也不会少不会乱？ A：

1. 所有线程产生日志消息，统一推送到线程安全消息队列。
2. 后台日志线程处理持久化保存，保证日志落盘有序、不丢失。
3. 界面更新使用委托Invoke/BeginInvoke，仅UI主线程操作表格控件。
4. 每条日志自带唯一序号，界面展示和文件保存使用同一条日志实体，保证一一对应。
5. 禁止多线程直接操作UI表格控件。

## 30组

Q1：正运动运动控制卡如何使用，如何确定到达指定点位？ A：

1. 使用步骤：先安装驱动、加载运动卡动态库；初始化运动卡，脉冲输出、IO端口配置；设置轴参数（速度、加速度）；下发点位运动指令启动运动。
2. 判断点位到达：方式一，读取轴状态寄存器，判断**到位信号（InPos）**；方式二，读取当前编码器坐标，对比目标坐标，在设定误差范围内判定到位；两种方式配合使用，增加可靠性。

Q2：modbus第三方协议报文 是什么？ A：

1. Modbus报文是主从设备之间传输的二进制消息帧，分为Modbus-RTU（串口）、Modbus-TCP（网口）。
2. RTU报文：从站地址 + 功能码 + 数据段 + CRC校验；TCP报文：MBAP报文头 + 功能码 + 数据段。
3. 功能码用来区分操作：读线圈、读保持寄存器、写单个寄存器、写多个寄存器等；校验位用来校验传输数据是否出错。

Q3：Modbus通信如何调用 A：

1. 项目一般使用第三方库如NModbus，不需要自己手写底层报文。
2. 第一步：创建Modbus客户端，建立TCP/串口连接。
3. 第二步：调用库提供API，选择对应功能码，读写线圈/寄存器。
4. 第三步：通信增加超时、重连、异常捕获；读写完成后释放连接资源。
5. 封装统一通讯接口，上层业务直接调用读写方法，不用关心底层报文细节。

Q4：代码中的异常怎么处理 A：

1. 使用try-catch-finally捕获异常，把可能报错的业务代码放入try块。
2. catch捕获对应类型异常，记录异常信息、堆栈到日志，方便定位问题；区分业务异常和系统异常，做不同处理。
3. finally用于释放资源，如串口、相机、文件句柄，无论是否异常都会执行。
4. 不要空catch，禁止只捕获不记录；顶层增加全局异常捕获，防止程序直接崩溃。
