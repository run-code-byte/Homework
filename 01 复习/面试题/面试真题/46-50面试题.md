Q4：怎么去除椒盐噪声 A：

1. **首选方法：中值滤波**，是非线性滤波，对椒盐噪声针对性最强，同时能较好保留边缘细节，是项目中最常用的方法。

2. 辅助方法

   ：

   - 形态学开运算（先腐蚀后膨胀），去除孤立的亮点噪点，适合噪声点偏小的场景。
   - 阈值分割+连通域筛选，按面积过滤掉小面积噪声点，适合噪声数量少、大小差异大的场景。
   - 多帧平均法，静态场景下多帧图像取平均，抑制随机椒盐噪声，适合静态检测工位。

3. 选型策略：噪声少用中值滤波即可；噪声严重时，先中值滤波再形态学处理，组合去噪。

Q5：中值滤波的原理，算法是什么样子的 A：

1. **原理**：属于**非线性空间滤波**，用像素邻域内所有像素灰度的中值，替换中心像素的灰度值，从而滤除偏离真实值较大的脉冲噪点。

2. 算法步骤

   ：

   - 选定N×N的滑动窗口（常用3×3、5×5），覆盖图像中每个像素。
   - 将窗口内所有像素的灰度值按大小排序。
   - 取排序后的中间值，作为窗口中心像素的新灰度值。
   - 窗口逐像素滑动遍历整幅图像，完成全图滤波。

3. **核心特点**：椒盐噪声的灰度值和周围差异极大，排序后会排在两端，不会被选中为中值，因此能有效去除；相比均值滤波，不会明显模糊图像边缘，细节保留更好。

Q6：识别瑕疵用什么方法 A： 以传统视觉算法为主，深度学习为辅，根据缺陷类型选择：

1. **灰度阈值法**：全局/局部阈值分割，提取和背景灰度差异明显的缺陷，比如缺料、污渍、针孔。
2. **Blob分析**：分割连通区域，通过面积、圆度、长度、宽度等特征筛选缺陷，适合斑点、孔洞类缺陷。
3. **边缘检测法**：提取工件边缘，通过边缘的缺口、凸起、毛刺判断缺陷，适合崩边、毛刺、轮廓不良。
4. **背景差分法**：待测图减去标准无缺陷背景图，通过差异提取缺陷，适合背景均匀、缺陷为局部差异的场景。
5. **模板对比法**：和标准模板做差分匹配，通过匹配度、差异区域判断缺陷，适合纹理、图案类缺陷。
6. **深度学习法**：YOLO/U-Net，识别不规则、背景复杂的划痕、异色等传统算法难以稳定检出的缺陷。

Q7：标定的方法 A： 项目中常用四类标定方法，对应不同场景：

1. **九点标定**：最基础，建立像素坐标与机械世界坐标的映射，用于2D定位、尺寸测量。
2. **旋转标定**：计算旋转中心，补偿旋转带来的坐标偏移，用于旋转台、带R轴的工位。
3. **手眼标定**：统一相机坐标系与机器人坐标系，用于机器人视觉引导、抓取对位。
4. **3D高度标定**：用标准高度块校准高度转换系数，建立像素偏移与真实高度的对应关系，用于3D高度、轮廓检测。

Q8：9点标定的原理 A：

1. 本质是**二维仿射变换**，通过9组对应点求解仿射变换矩阵，包含平移、旋转、缩放、剪切变换。
2. 原理公式：  `X = a·x + b·y + c`  `Y = d·x + e·y + f`  其中(x,y)是像素坐标，(X,Y)是机械世界坐标，a~f是6个仿射参数。
3. 通过9组标定点，用最小二乘法拟合求解最优的变换矩阵，比3点法更鲁棒，能同时校正镜头畸变、相机安装倾斜带来的误差。
4. 使用时，像素坐标乘以变换矩阵，即可换算出对应的机械世界坐标。

Q9：旋转标定是通过什么标定的 A： 通过**旋转台+标准标定板**完成标定：

1. 将标定板固定在旋转台中心，相机垂直拍摄。
2. 控制旋转台按固定间隔旋转多个角度（通常0°、30°、60°…330°，共12个角度），每个角度采集一次标定点的像素坐标。
3. 通过多个角度的标定点轨迹，拟合计算出旋转中心的像素坐标，以及角度与坐标偏移的对应关系。
4. 验证：旋转任意角度，用标定的旋转中心计算坐标，和实际坐标对比，验证精度。

Q6：上位机开发过程中出现页面假死或者卡死，怎么处理 A： 先定位根因，再针对性解决，按照以下流程排查：

1. **定位问题**：通过Visual Studio调试器，卡死时暂停查看主线程调用栈，定位阻塞的代码位置；结合性能监视器看CPU、内存、GDI对象，区分是计算阻塞、死锁还是内存泄漏。
2. 常见原因与解决
   - **耗时操作阻塞主线程**：将算法、IO、通讯、数据库等所有耗时操作全部移到后台线程/线程池/Task，主线程仅做UI渲染。
   - **UI频繁刷新卡顿**：降低界面刷新频率，批量更新数据，不用每帧全量刷新；大图像渲染采用双缓冲，减少界面闪烁与卡顿。
   - **死锁阻塞**：检查lock嵌套顺序，统一加锁顺序，细化锁粒度；用读写锁替代独占锁，避免UI线程与后台线程锁竞争。
   - **内存/GC卡顿**：大图像用内存池复用，避免频繁创建销毁大对象；及时释放非托管资源，减少GC阻塞。
3. **兜底机制**：界面增加超时检测，后台任务超时自动取消，避免永久阻塞UI。

Q7：主线程还会卡死吗 A： 严格遵守“耗时操作全放后台、UI线程只做渲染”的规范，常规场景下不会卡死。 但极端场景下仍可能出现阻塞：

2. UI线程中执行lock等待，后台线程持有锁不释放，形成死锁；
3. 短时间内大量UI消息堆积，比如高频刷新界面、频繁更新控件，消息队列处理不过来。 工程中会通过限制UI刷新频率、避免UI线程加锁、使用异步UI更新、双缓冲渲染等手段，彻底规避主线程卡死问题。

Q13：图像的数据结构 A： 内存中图像本质是**二维像素数组**，按行优先存储：

1. **8位灰度图**：`byte[,]`二维字节数组，每个元素对应一个像素的灰度值，范围0~255；每行像素连续存储，包含有效像素和行对齐填充（步长Stride）。
2. **24位彩色图**：每个像素占3字节，依次存储B、G、R三个通道分量；也可按通道分离为三个独立的二维数组。
3. **3D高度图**：`float[,]`二维浮点数组，每个元素对应坐标点的高度值，单位mm。
4. 附加属性：图像宽度、高度、位深、行步长、像素格式，是图像数据的元信息。

Q14：写上位机的时候，异常的处理或者全局的捕获怎么做 A： 采用**分层捕获+全局兜底**的异常处理机制：

1. 分层处理
   - 底层方法（设备IO、通讯、数据库）：用try-catch捕获具体类型异常，记录详细日志（异常信息、堆栈、参数），按需向上抛出业务异常，禁止空catch。
   - 业务逻辑层：捕获底层异常，做重试、降级、超时处理，比如通讯异常自动重连、数据异常使用默认值。
   - UI层：捕获业务异常，弹窗提示用户，不崩溃程序。
2. 全局兜底捕获
   - WinForm：订阅`Application.ThreadException`事件，捕获UI线程未处理异常；
   - WPF：订阅`DispatcherUnhandledException`事件，处理调度线程未捕获异常；
   - 全程序：订阅`AppDomain.CurrentDomain.UnhandledException`，捕获非UI线程的未处理异常，记录致命日志，保存现场数据，友好提示后安全退出程序。

Q1：值类型和引用类型有哪些 A：

1. 值类型

   ：存储在栈内存中，赋值时拷贝完整数值，生命周期随作用域自动释放。

   - 包含：数值类型（int、double、float、byte、decimal）、bool、char、枚举enum、结构体struct（如Point、Size、自定义检测参数结构体）。

2. 引用类型

   ：存储在堆内存中，赋值时拷贝内存引用地址，多个引用可指向同一个对象，由GC回收。

   - 包含：类class（如图像对象、相机类、通讯类）、string、数组、委托、接口、object。

3. 项目中典型场景：检测结果结构体用值类型，传递高效；图像、设备对象用引用类型，避免大对象拷贝开销。

Q2：装箱与拆箱机制 A：

1. **装箱**：将值类型转换为引用类型（object或接口）的过程。系统会在堆中分配内存，拷贝值类型的数据，返回对应的引用地址。
2. **拆箱**：装箱后的引用类型转换回值类型的过程。先检查类型匹配，再将堆上的值拷贝到栈上的值类型变量中。
3. **性能影响**：频繁装箱拆箱会增加GC压力、带来额外的内存和性能开销，高频图像循环、像素处理场景影响尤为明显。
4. **项目实践**：优先使用泛型集合（如`List<T>`）替代非泛型集合（如ArrayList），避免隐式装箱；像素级处理循环中避免值类型到object的转换。

Q3：参数修饰符 A： C#常用四个参数修饰符，作用与场景各有不同：

1. **ref**：按引用传递，参数必须在调用前赋值，方法内可读取也可修改。适合需要修改多个值的场景，比如标定计算同时返回XY两个方向的偏差。
2. **out**：输出参数，方法内部必须为其赋值，调用前无需赋值。用于方法返回多个结果，比如检测方法同时输出缺陷数量、最大面积、缺陷位置。
3. **in**：只读按引用传递，方法内只能读取不能修改。用于传递大体积结构体，避免值拷贝开销，提升性能，比如传递大尺寸的检测参数配置。
4. **params**：可变长度参数数组，只能作为最后一个参数。用于参数数量不确定的场景，比如多ROI区域检测方法。

Q4：类型转换有哪些，as和is的具体区别和应用场景 A：

类型转换分类

1. **隐式转换**：小范围转大范围，无精度损失，编译器自动完成，比如int转double、子类引用转父类引用。
2. **显式转换（强制转换）**：大范围转小范围，可能有精度损失，需要手动强转，比如double转int。
3. **自定义转换**：通过`implicit`/`explicit`运算符定义自定义转换规则，比如像素坐标转物理坐标。

as与is的区别

1. is

   ：类型判断运算符，返回bool值，仅判断对象是否匹配目标类型，不做转换。

   - 应用场景：类型合法性校验，比如判断图像是灰度图还是彩色图、判断设备是否支持指定功能。

2. as

   ：安全类型转换运算符，仅用于引用类型，转换成功返回对应类型对象，失败返回null，不抛出异常。

   - 应用场景：引用类型的安全转换，比如将object类型的设备对象转为具体的相机类型。

3. **核心区别**：is只判断不转换；as只转换不抛异常，性能优于“is判断+强制转换”，仅做一次类型检查。

Q5：创建线程有哪些 A： C#实现多线程有五类主流方式，适配不同场景：

Q7：泛型是什么，具体又是怎样使用的 A：

定义

泛型是一种**类型参数化**的编程机制，定义类、方法、接口时使用类型占位符，调用时再指定具体类型。既实现了代码复用，又保证类型安全，避免装箱拆箱的性能损耗。

1. **泛型类**：比如通用线程安全队列`ConcurrentQueue<T>`，项目中图像队列实例化为`ConcurrentQueue<Bitmap>`；还有通用设备接口`IDevice<T>`，适配不同设备的数据类型。

4. 项目价值：通用检测模块通过泛型适配不同图像类型、结果类型，不用重复开发多套代码，同时兼顾类型安全与性能。
