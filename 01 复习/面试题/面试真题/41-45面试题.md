Q2：中值滤波作用 A：

1. 属于**非线性空间滤波**，原理是用像素邻域内所有像素灰度的中值，替换中心像素的灰度值。
2. 核心作用：有效去除**椒盐噪声、脉冲噪声、斑点噪声**，同时相比均值滤波，能更好地保留图像边缘细节，不会造成明显的边缘模糊。
3. 项目中常用于预处理去除成像中的颗粒噪点、传感器随机噪声，提升后续边缘提取、缺陷检测的稳定性。

Q3：lock的含义 A：

1. lock是C#中用于**多线程同步**的关键字，作用是给代码块加互斥锁。
2. 保证同一时刻最多只有一个线程进入lock包裹的代码段，防止多线程同时操作共享资源时，出现数据竞争、状态不一致、资源损坏的问题。
3. 使用时需控制锁粒度，避免嵌套锁，防止死锁；优先锁定私有只读对象，避免锁定公开对象引发意外。

Q4：c#的三大特性 A：

1. **封装**：将数据、方法、内部实现细节包装在类内部，对外只暴露必要的接口，隐藏内部细节，降低耦合，提升安全性与可维护性。项目中相机、通讯、日志模块均做封装。
2. **继承**：子类可以继承父类的属性和方法，复用公共代码，减少冗余，支持扩展。项目中定义设备基类，不同品牌相机继承基类，复用通用逻辑。
3. **多态**：父类引用指向子类对象，不同子类对同一方法有不同实现，调用时自动匹配对应逻辑，提升程序扩展性。项目中通过接口多态，实现不同品牌相机的统一调用。

Q5：线程池的意义是什么 A：

1. **降低资源开销**：复用线程，避免频繁创建、销毁线程带来的性能开销与内存消耗。
2. **提升响应速度**：任务到达时直接复用已有线程执行，无需等待线程创建，提升任务响应速度。
3. **统一管理调度**：自动管控线程数量、任务队列、线程生命周期，避免无限创建线程导致系统资源耗尽。
4. 项目中常用于图像处理、日志写入、通讯响应等大量短耗时任务，提升系统吞吐。

Q6：常用的图像处理工具 A：

1. 商业视觉平台：VisionPro、海康VisionMaster、Halcon，用于快速搭建工业视觉检测流程，项目主力使用。
2. 开源算法库：OpenCV/OpenCVSharp、EmguCV，用于开发自定义图像处理算法，补充商业软件的定制化需求。
3. 基础类库：System.Drawing、Bitmap，用于基础图像操作、格式转换、界面渲染。

Q7：了解图像处理的滤波金字塔吗 A：

1. 图像金字塔是图像的**多分辨率表示**，通过逐层下采样得到不同尺寸的图像层级，类似金字塔结构。
2. 滤波金字塔就是在金字塔的不同分辨率层级上，分别做滤波与特征提取。
3. 常见的高斯金字塔用于降采样，拉普拉斯金字塔用于残差重建；多尺度滤波可以检测不同大小的缺陷与特征，提升检测鲁棒性，也可用于加速图像处理、实现多尺度匹配。

Q8：序列化与反序列化 A：

1. **序列化**：将内存中的对象实例，转换成可存储、可传输的数据格式（如JSON、二进制、XML）。
2. **反序列化**：将存储/传输的序列化数据，还原成内存中的对象实例。
3. 项目中主要用于保存视觉参数、设备配置、产品配方，实现配置的持久化存储、导入导出与跨设备复用。

Q9：visionpro的3d工具中上下镭射双镭射标定了解吗 A：

1. 了解，是VisionPro 3D激光工具中，针对上下双激光轮廓仪的**坐标统一标定**。
2. 原理：使用统一标定板，分别采集上下两个激光的标定数据，计算两个激光坐标系之间的变换矩阵，将两路激光数据统一到同一个世界坐标系下。
3. 作用：消除上下激光的安装偏差、角度偏差，实现工件上下表面轮廓数据的对齐、拼接与尺寸计算，保证双面检测的基准一致、尺寸准确。

Q10：zmc系列控制器是板卡吗，为什么用到运动控制卡 A：

1. ZMC是正运动的运动控制器，既有**PCI/PCIe接口的板卡式**，也有独立式总线控制器。
2. 使用运动控制卡的原因：
   - 实时性高，能实现高精度点位控制、多轴联动、轨迹规划，响应速度远优于普通PLC。
   - 支持编码器高速锁存、硬触发输出，精准配合飞拍、视觉定位的触发同步。
   - 适合视觉引导、精密对位、高速飞拍等对运动精度、实时性要求高的场景。

Q11：偏振片的作用 A：

1. 只允许特定振动方向的光线通过，过滤掉其他方向的偏振光。
2. 视觉检测中的核心作用：
   - 消除金属、玻璃、塑料等高反光工件表面的镜面反射光、杂散光，避免亮斑、过曝。
   - 提升表面缺陷的对比度，突出划痕、凹坑等表面形貌特征，减少反光干扰。
   - 配合同轴光源、环形光源使用，优化成像质量，降低缺陷误检率。

Q14：搜索相机用的是哪个方法 A： 调用相机原厂SDK提供的**设备枚举方法**，比如海康SDK的`MV_CC_EnumDevices`，遍历网卡下所有相机设备，获取设备名称、IP、序列号，再选择对应设备建立连接。上层封装时统一成`ICamera`接口的`EnumCameras`方法。

Q15：实时图像是怎么实现的 A： 相机开启连续采集模式，注册图像回调函数，相机每采集一帧就触发回调；拿到图像数据后，通过`Invoke/BeginInvoke`切回UI主线程，更新到界面图像控件上，实现实时预览。同时做帧率控制，避免界面刷新占用过多资源。

Q16：实时取像和单次采像有什么区别 A：

- **实时取像**：连续采集模式，相机持续曝光采图，不断回调输出图像，用于界面预览、调试调参，不做正式检测。
- **单次采像**：触发模式，收到触发信号才采图一次，输出单张图像用于正式检测，定位精度高、时序可控，是产线检测的常用模式。

Q17：实时画面是间隔多久采集一张图像 A： 根据相机帧率和界面刷新需求调整，一般实时预览控制在**10~20帧/秒**，也就是间隔50~100ms采集一张。调试时可以拉满帧率，正常运行时降低预览帧率，节省资源给算法处理。

2. **软件配置**：C# WinForm上位机，VisionPro视觉流程，Modbus-TCP通讯，九点标定+吸嘴偏差标定。
3. **完整流程**：工件上料到位→传感器触发→相机单次采图→PatMax定位工件XYR坐标→九点标定转机械坐标→计算偏移量→下发机器人→机器人带动吸嘴贴标→贴完复检位置→结果输出到PLC→下料。

Q19：引导定位有几个吸嘴 A： 常规单工位贴标项目用1个吸嘴；高速多头贴标项目用到过4个吸嘴，对应多个贴标位置，视觉一次定位，分别补偿每个吸嘴的偏差。

Q20：有一个相机是定位吸嘴的？放料位也有一个相机吗 A： 是的，高精度贴标是双相机方案。**上相机（顶视）定位工件，下相机（仰视）定位吸嘴**，做吸嘴偏差标定；放料位也有定位相机，校准放料位置。两个相机分别标定，最终统一到机器人坐标系，实现上下精准对位。

Q21：两个相机是怎么标定的 A：

1. 分别做九点标定：上相机标定像素坐标到机器人工作台坐标系，下相机标定像素坐标到吸嘴末端坐标系。
2. 坐标系统一：用标准标定块，两个相机同时拍摄，计算两个相机坐标系之间的变换矩阵，把两路坐标统一到机器人基坐标系下，消除安装偏差。
3. 吸嘴偏差标定：记录吸嘴偏心、旋转偏差，贴标时做实时补偿。

Q22：下相机做了什么标定，上相机做了什么标定 A：

- **下相机**：九点标定 + 吸嘴中心标定，建立像素坐标和吸嘴末端的坐标关系，标定吸嘴的偏心、旋转偏差。
- **上相机**：九点标定，建立像素坐标到机器人工作台世界坐标的映射关系，用于定位工件位置。

Q23：用标定抓取的是哪个特征呢 A： 抓取的是工件上的**定位Mark特征**，比如圆形定位孔、对角标记点，或者工件的轮廓边角；用PatMax匹配这些特征，输出精准的XYR坐标，代入标定矩阵换算成机械坐标，控制机器人抓取。

Q24：旋转中心标定拍了几次 A： 常规项目拍**12次**，均匀分布0~360°，每30度拍一次，采集每个角度的标定点坐标，拟合计算旋转中心。高精度项目会拍18次，角度间隔更小，标定精度更高。

Q25：九点标定之后怎么看看你标定的有没有问题 A：

1. 看标定输出的**RMS均方根误差**，常规项目RMS小于0.02像素合格，高精度项目要小于0.01像素。
2. 验证点测试：移动平台到额外的3~5个验证位置，用视觉算出坐标，和机械实际坐标对比，计算绝对误差，在公差范围内则合格。
3. 重复测试：同一点多次测量，看重复定位精度，判断标定稳定性。

Q26：除了 rms 还要看什么 cpk A： 除了RMS标定残差，还要看三项核心指标：

1. **绝对误差**：验证点的视觉测量值和真实值的偏差，直接反映准确度。
2. **CPK（过程能力指数）**：用多次重复测量的数据计算，衡量测量系统的稳定性和一致性，量产项目一般要求CPK≥1.33。
3. **最大误差**：所有验证点中的最大偏差，确保最坏情况也在公差范围内。

Q27：相机没取到图像一般是哪些原因导致的 物理层面会有哪些原因 A： **软件层面**：触发模式配置错误、触发信号未接收、SDK连接断开、IP配置错误、图像回调异常、缓冲区满、线程阻塞。 **物理层面**：相机供电异常、网线/数据线松动断开、光源不亮导致画面全黑、镜头光圈关死/对焦完全模糊、触发传感器故障未发出信号、工件完全遮挡视野。

Q28：脚本如果有问题的话，调试的话一般是怎么做的，说一下操作流程 A：

1. 稳定复现：固定输入条件，稳定复现问题。
2. 分步拆解：把视觉流程拆成采集、预处理、定位、检测几个步骤，单步运行，定位出问题的环节。
3. 中间结果验证：每一步保存输出图像，对比预期结果，定位出问题的算子。
4. 参数调试验证：调整对应算子的参数，验证参数合理性。
5. 代码调试：C#脚本打断点，查看变量值、输入输出，排查逻辑错误。
6. 回归验证：修复后用多组样本测试，确认问题解决且不引入新问题。

Q29：高级脚本有问题怎么在 visual studio 查看 A：

1. 把VisionPro脚本工程附加到Visual Studio，或者将脚本代码导出到VS项目中。
2. 在脚本关键位置加断点，启动调试，VisionPro运行时触发断点，查看变量值、调用栈。
3. 用日志输出中间变量，跟踪执行流程，定位异常代码行。
4. 捕获异常信息，查看异常堆栈，精准定位出错位置。

Q30：都能运行结果不对怎么办 A： 按照从输入到输出的顺序逐层排查：

1. 查输入：确认图像是否正常，有没有过曝过暗、视野偏移、特征缺失。
2. 查定位：确认定位是否准确，ROI是否偏移，角度是否正确。
3. 查参数：检查检测阈值、滤波参数、判定规则、公差设置是否合理。
4. 查标定：确认标定是否失效，坐标转换是否存在偏差。
5. 查逻辑：检查判定逻辑、数据换算、输出公式是否有误，分步输出中间值对比验证。

Q31：pma 精细和粗糙都是什么颜色 A： PatMax中，**粗糙模型（粗定位）默认蓝色**，用于快速锁定大概位置；**精细模型（精定位）默认绿色**，在粗匹配基础上做高精度对位，输出最终坐标。

Q32：用的是 和 mes 弹性是什么概念 A： 项目里会和MES系统对接，弹性指接口的适配灵活性。我们的对接层做配置化设计，支持灵活调整字段、协议、数据格式，不用修改核心代码就能适配不同客户的MES系统，降低对接成本。

Q33：计分是考虑杂斑呢 A： PatMax匹配得分会考虑特征完整度，匹配区域内的杂斑、干扰点会被当成无效特征，降低匹配得分；杂斑过多会导致匹配失败。 项目中一般会先做ROI裁剪、预处理去噪，过滤杂斑干扰，再执行匹配。

Q34：匹配角度范围一般设置多少 A： 常规工件角度偏差小的场景，设置**±15°~±30°**；旋转工位、角度偏差大的场景，设置±90°甚至±180°全角度匹配。 角度范围越大匹配速度越慢，满足工况的前提下尽量缩小范围，提升检测速度。

Q35：上下限比较大会有什么影响 A： 匹配角度上下限设置太大，匹配搜索范围变大，**匹配速度变慢、耗时增加**；同时容易匹配到错误的相似特征，误匹配概率上升，定位稳定性下降。

Q36：匹配多了怎么办，得分很近 A：

1. 优化ROI，缩小匹配区域，排除多余的相似特征。
2. 提高匹配得分阈值，过滤低分错误匹配。
3. 增加角度、尺寸约束，排除不符合的匹配结果。
4. 选择工件上独有的特征制作模板，避免相似干扰。
5. 得分接近时，取得分最高的结果，再做二次特征验证，确认正确性。

Q37：找线工具过滤一半像素 A： 指找线工具的**半像素滤波**，对边缘做亚像素级的平滑滤波，去除像素级的边缘锯齿，让边缘更平滑，提升找线的精度和重复性，多用于高精度尺寸测量场景。

Q38：卡尺积分函数用过吗 A： 用过，VisionPro卡尺工具里的积分函数，作用是沿卡尺方向对灰度做积分，增强边缘对比度，抑制噪声，提升弱边缘的检出能力。低对比度、噪声大的场景下，开启积分可以更稳定地找到边缘。

Q39：sy 角度和 getpose 的区别 A：

- **SY角度**：仅输出图像坐标系下的2D旋转角度值，信息单一。
- **GetPose**：输出完整位姿，包含XY坐标、旋转角度，还有缩放、倾斜等仿射变换参数，信息更全，用于坐标转换、标定对位。

Q40：用过哪些预处理的方法 A：

1. 滤波类：中值滤波、高斯滤波、均值滤波，去噪平滑。
2. 灰度变换：灰度拉伸、直方图均衡、对比度增强，提升缺陷对比度。
3. 图像变换：ROI裁剪、旋转校正、仿射变换，对齐检测区域。
4. 形态学处理：腐蚀、膨胀、开运算、闭运算，去除小噪点、连接断裂区域。
5. 背景差分：减去背景图，突出前景缺陷。

Q41：中值和高斯的区别 A：

1. **原理不同**：中值滤波是非线性滤波，取邻域灰度中值；高斯滤波是线性滤波，用高斯核做加权平均。
2. **去噪类型不同**：中值擅长去除椒盐噪声、脉冲噪声、斑点；高斯擅长去除高斯噪声、随机噪声，整体平滑。
3. **边缘保留不同**：中值滤波能更好保留边缘细节，不会明显模糊边缘；高斯滤波会模糊边缘，降噪越强边缘越糊。
4. **适用场景不同**：中值用于颗粒噪点多的场景；高斯用于整体噪声均匀、需要平滑的场景。

Q42：黑色背景白色粉尘颗粒，有什么方法处理 A：

1. 成像优化：背光源透射照明，突出粉尘颗粒，让背景更均匀，提升对比度。
2. 预处理：中值滤波去除微小噪点，灰度拉伸增强颗粒对比度。
3. 检测：Blob分析，设置面积、圆度阈值，筛选真实粉尘颗粒，过滤噪声点。
4. 阈值优化：用局部动态阈值分割，适应背景不均匀的情况。
5. 运动场景下，用多帧平均去除背景噪声，再差分提取颗粒。

Q43：有 abc 形状物体，如果用 pma 识别怎么进行分类 A：

1. 分别制作A、B、C三个形状的PatMax模板。
2. 图像中依次用三个模板匹配，每个模板输出匹配得分和位置。
3. 取得分最高且超过阈值的模板对应的形状，作为识别结果。
4. 增加尺寸、角度约束，排除错误匹配，提升准确率。
5. 形状差异较小时，结合几何尺寸、特征点做二次校验。

Q44：硬件选项评估有没有做过 A： 做过，项目前期都会做硬件评估选型。根据客户的视场、精度、节拍、缺陷大小、工件材质，评估相机分辨率、帧率、快门类型，匹配镜头焦距、景深、靶面，搭配光源类型、角度、功率，输出完整硬件方案，并且打样验证成像效果，确认可行性。

Q45：白色背景红色粉尘，选什么光源 A： 优先选**红色同轴光源或红色低角度环形光源**。红色光源与粉尘颜色匹配，增强粉尘亮度对比度；同轴光垂直入射，突出表面颗粒特征，白色背景反射均匀，红色粉尘呈现清晰亮斑，对比度高。可搭配偏振片减少背景反光。

Q46：光圈越小景深越怎么？ A： 光圈越小，**景深越大**，画面中清晰的范围越大；光圈越大，景深越小，只有焦点附近清晰。视觉检测中一般适当缩小光圈，获得足够景深，保证工件高低起伏范围内都清晰。

Q47：相机的靶面尺寸，工作距离，焦距，视野的大小，关系 A： 核心近似公式：**视野大小 = 工作距离 × 靶面尺寸 / 焦距**。

- 焦距不变，工作距离越远，视野越大。
- 工作距离不变，焦距越短，视野越大。
- 视野不变，靶面越大，所需焦距越长。
- 靶面是相机固定参数，靶面越大，相同焦距和工作距离下视野越大。

Q48：fa 镜头和远心镜头的区别 A：

1. **成像原理**：FA镜头是透视成像，近大远小，存在透视畸变；远心镜头消除透视畸变，景深范围内放大率恒定，工件高低不影响成像尺寸。
2. **精度**：FA镜头精度低，受物距变化影响大；远心镜头精度高，测量稳定。
3. **成本体积**：FA镜头体积小、成本低；远心镜头体积大、价格高。
4. **适用场景**：FA镜头用于普通定位、外观检测；远心镜头用于高精度尺寸测量、精密检测场景。

Q49：卷帘相机和全局相机的应用区别 A：

- **卷帘快门**：逐行曝光，成本低、帧率高；运动物体会产生果冻效应、拖影。用于静态工件检测、低速场景、普通外观检测。
- **全局快门**：整幅同时曝光，运动无拖影；同分辨率下帧率更低、成本更高。用于飞拍、运动工件、高速在线检测、视觉引导场景，保证运动中成像清晰无畸变。

3. 形貌检测：平面度、平行度、轮廓度检测。

Q53：说一下 3d 相机测试高度的工作流程 A：

1. **标定**：用标准高度块做高度标定，建立像素偏移量与真实高度的对应关系，校准基准平面。
2. **扫描**：3D相机沿工件运动，逐行采集轮廓数据，生成高度图/点云。
3. **预处理**：点云去噪、平滑滤波，去除异常噪点。
4. **基准拟合**：拟合基准平面，作为高度测量的零基准面。
5. **测量计算**：提取目标区域的高度值，计算相对基准面的高度差、最大/最小高度。
6. **判定输出**：对比公差阈值，输出OK/NG结果和高度数值。

## 43组

Q1：项目中用到了几个相机，怎么检测的？ A：

1. 单相机项目：常规单工位外观检测、单工位视觉引导，用1台面阵相机；线扫卷材检测用1台线扫相机。流程：工件到位触发采图→定位对齐ROI→预处理→缺陷提取/定位计算→判定输出结果。
2. 多相机项目：多面外观检测最多用到6台相机，分别对应工件不同面，上位机统一调度触发、分配算法线程、汇总结果；双面对位引导项目用2台相机，上下各1台，分别定位工件和治具，做坐标统一后对位。
3. 3D检测项目：单工位用1台3D线激光轮廓仪，完成高度、轮廓、平面度检测。

Q2：3D线扫是怎么扫的？ A：

1. 核心原理基于激光三角测量法：线激光器向工件投射一条激光线，CMOS传感器以固定夹角接收反射光，通过条纹偏移量计算高度，得到一行轮廓数据。
2. 扫描方式：依靠**工件与相机的相对匀速运动**，逐行采集每一行的轮廓高度数据，最终拼接成完整的二维高度图或三维点云数据。
3. 运动实现：产线检测由流水线带动工件运动，相机固定；复杂工件检测由机械臂带动3D相机运动，工件固定。

Q3：3D线扫过程中流水线也需要跟着动吗？ A： 分两种场景：

1. **在线产线检测**：流水线必须匀速运动，带动工件连续通过检测位，相机固定不动，边运动边扫描，是量产线最常用的方式。
2. **固定工位检测**：流水线不动，工件定位在治具上，由运动模组或机械臂带动3D相机匀速移动扫描，多用于复杂工件、多工位柔性检测。

Q4：流水线是什么类型？ A：

1. 常规零部件检测：**倍速链流水线、皮带输送线**，带挡块定位，工件逐工位流转。
2. 卷材、极片检测：**放卷-收卷流水线**，张力控制，匀速走料，配合线扫相机连续检测。
3. 高精度检测：**直线电机运动平台、丝杆模组**，重复定位精度高，带动工件/相机做高精度扫描运动。

Q5：3D相机用的哪个牌子的？ A： 项目里用过两个品牌：

1. **海康威视线激光轮廓仪**：性价比高，国产适配好，常规3D检测、高度测量项目使用。
2. **基恩士3D线扫相机**：高精度、高稳定性，高端精密测量、微小缺陷检测项目使用。

Q6：怎么操控机械臂的？ A：

1. 通讯方式：通过**TCP/IP以太网**和机器人控制器建立连接，走机器人专用通讯协议，部分支持Modbus-TCP。
2. 操控流程：视觉计算出工件偏移量和角度→上位机把坐标数据下发给机器人控制器→机器人控制器解析后执行点位运动、旋转补偿→运动完成后反馈完成信号给上位机。
3. 辅助信号：硬IO信号做握手、触发、安全联锁，保证时序安全。

Q7：得到的物件大小x/y/z与实际大小有偏差，怎么解决的？ A：

1. XY平面尺寸偏差：
   - 重新做九点标定，校准像素当量，修正相机安装倾斜、镜头畸变。
   - 用高精度标准块做尺寸标定，计算固定补偿系数，修正系统误差。
   - 优化定位算法，用亚像素定位提升边缘提取精度。
2. Z轴高度尺寸偏差：
   - 用标准高度块做3D高度标定，校准高度转换系数，修正激光角度偏差。
   - 重新拟合基准平面，消除基准面倾斜带来的整体偏差。
   - 做温度补偿，抵消温度漂移带来的测量偏差。
3. 通用优化：多次测量取平均值，降低随机误差；定期校准标定，保证长期稳定性。

Q8：得到的物件位置与实际位置有偏差怎么解决的？ A： 按照从易到难排查解决：

1. 基础排查：检查相机是否松动、治具是否偏移、工件定位是否到位，排除硬件位移。
2. 标定校准：重新做九点标定，验证标定残差，确保坐标转换矩阵准确；有旋转工位补充旋转中心标定，补偿旋转偏移。
3. 工具补偿：机器人抓取类项目，做吸嘴/夹爪中心偏差标定，补偿工具偏心。
4. 软件修正：用标准件多次测量，计算固定位置偏差值，写入程序做坐标补偿。
5. 精度验证：复测验证偏差在公差范围内，固化参数。

Q9：测量pin针都是测量什么数据？怎么测量的？得到的3D数据是什么格式的？ A：

1. 测量数据：pin针高度、根部直径、尖部直径、圆度、位置度、共面度、针尖倒角尺寸、针身弯曲度。
2. 测量方法：3D线激光轮廓仪沿pin针轴向扫描，获取完整轮廓点云；提取pin针顶部、根部的截面轮廓；拟合计算直径、高度、圆度等参数；多根pin针联合计算共面度、位置度。
3. 3D数据格式：
   - 高度图：二维数组，每个元素对应位置的高度值，类图像格式。
   - 点云数据：XYZ三维坐标点集，每行对应一条轮廓。
   - 轮廓数组：单条扫描线的高度值数组。

Q10：怎么计算共面度的？ A：

1. 数据采集：3D扫描获取所有被测pin针/测点的三维坐标。
2. 基准拟合：用最小二乘法拟合所有测点的基准平面，作为共面度的参考基准。
3. 偏差计算：逐个计算每个测点到基准平面的垂直距离。
4. 结果计算：取所有点中最大距离与最小距离的差值，就是共面度（平面度），代表被测面的平整程度。
5. 高精度场景用最小包容区域法，用两个平行平面包容所有测点，平面间距即为共面度，结果更严谨。

Q11：精度/像素大概多少？实际精度多少？ A：

1. 2D视觉

   ：

   - 常规项目：单像素精度0.050.1mm，实际重复定位精度±0.02±0.05mm。
   - 高精度项目：单像素精度0.010.02mm，实际测量精度±0.005±0.01mm。

2. 3D视觉

   ：

   - Z轴单像素高度分辨率0.0050.02mm，实际高度测量精度±0.01±0.05mm，随量程增大精度略有下降。

Q12：值类型和引用类型都有哪些数据？区别是什么？ A：

1. **值类型**：int、double、float、bool、char、struct、enum，存储在栈内存中，赋值时拷贝完整数值，两个变量相互独立，修改互不影响。
2. **引用类型**：class、string、数组、委托、接口，存储在堆内存中，赋值时拷贝内存引用地址，多个引用指向同一个对象，修改会影响所有引用。
3. 核心区别：存储位置不同、赋值方式不同、内存回收机制不同；值类型无继承，引用类型支持继承。

Q13：委托是什么？委托的作用，为什么要用到委托，用不同方法就能解决为什么还要用委托？ A：

1. 委托是C#中的一种类型，可以理解为**类型安全的函数指针**，能够存储方法的引用，包括方法的参数列表和返回值类型。
2. 核心作用：实现回调机制、解耦调用方与实现方、支持多播链式调用，是事件的底层基础。
3. 为什么用委托而不是直接调用方法：
   - 直接调用是强耦合，调用方必须知道具体方法名；委托可以动态绑定方法，运行时指定具体实现，扩展性更强。
   - 适合回调场景：比如相机采图完成、检测完成，通过委托通知业务层，底层模块不用依赖上层业务，实现解耦。
   - 支持多播：一个委托可以绑定多个方法，一次调用依次执行，适合事件通知场景。
   - 符合开闭原则：新增业务方法不用修改调用代码，只需绑定委托。

Q14：事件和委托的区别 A：

1. 本质关系：事件是委托的**封装**，事件内部基于委托实现。
2. 访问权限不同：
   - 委托可以直接赋值、直接调用、清空整个委托链，外部可以任意修改，安全性低。
   - 事件只能通过`+=`添加方法、`-=`移除方法，外部不能直接调用事件、不能直接赋值整个委托链，封装性和安全性更高。
3. 使用场景不同：委托用于回调、传递方法；事件用于对象间的状态通知、事件发布订阅。
4. 类型属性不同：委托是一种类型；事件是类的成员，依附于类存在。

Q15：怎么实现多线程的？ A： 采用分层多线程架构，按模块拆分线程：

1. UI主线程：仅负责界面渲染、用户交互，不执行任何耗时操作。
2. 图像采集线程：独立长线程，监听触发信号，控制相机采图，图像写入线程安全队列。
3. 算法处理线程池：从队列取图，执行视觉检测、定位、测量算法，多图并行处理。
4. 后台常驻线程：处理PLC通讯、日志存储、心跳检测，不占用业务线程。
5. 实现手段：长生命周期线程用`Thread`类；短任务用`ThreadPool`线程池；异步操作用`Task`+`async/await`；通过`lock`、线程安全队列保证资源安全。

Q16：线程池的编程定义是什么？ A： 线程池是一种**线程资源管理机制**，内部维护一组可复用的工作线程，统一管理线程的创建、复用、销毁和任务调度。 任务到来时直接复用池中空闲线程执行，避免频繁创建销毁线程的性能开销，同时限制线程最大数量，防止无限创建线程耗尽系统资源。.NET中通过`ThreadPool`类提供线程池能力，自动管理线程生命周期与任务队列。

Q17：第一个线程里面创建了第二个线程，第二个线程里面有while循环，如何停止第二个线程，如果加了bool变量，线程1和线程2使用的时候不会冲突吗？怎么解决的？具体用的是哪一个方法？怎么实现的？ A：

1. **停止方法**：用**停止标志变量**控制循环退出，是工业开发最常用的安全停止方式。

2. 冲突与解决

   ：

   - 普通bool变量存在多线程内存可见性问题，线程1修改后线程2可能无法立刻感知。
   - 解决：用`volatile`关键字修饰bool变量，强制所有线程直接从内存读取值，保证修改对所有线程立即可见；如果是更复杂的状态操作，用`Interlocked`原子操作或`lock`锁。

3. 具体实现

   ：

   - 定义停止标志：`private volatile bool _isRunning = true;`
   - 第二个线程循环：`while(_isRunning) { 执行业务逻辑 }`，循环结束线程自然退出。
   - 第一个线程停止：`_isRunning = false;`，随后调用`thread2.Join()`等待线程安全退出，释放资源。

4. 更规范的方案：使用`CancellationToken`取消令牌，支持超时、联动取消，是.NET推荐的标准取消方式。

C#开发技术问题

**Q3：C#中多线程有哪几种实现方式？** A：

1. **Thread类**：手动创建独立线程，用于长生命周期、常驻的任务，比如图像采集线程、通讯监听线程，可精细控制线程优先级、后台状态。
2. **ThreadPool线程池**：系统管理的线程池，复用线程，适合大量短耗时任务，比如图像处理、日志写入，减少线程创建销毁开销。
3. **Task + async/await**：基于任务的异步编程模型，是.NET推荐的主流方式，适合异步IO、耗时任务，代码简洁，支持取消、异常处理，项目中通讯、数据库操作大量使用。
4. **Parallel类**：并行循环，用于批量数据并行处理，比如多图批量检测、多区域并行计算。
5. **BackgroundWorker**：WinForm老式后台组件，适合简单的后台任务+UI进度更新，新项目已较少使用。

**Q4：多线程开发里，如何避免出现线程数据竞争问题？** A： 按方案优先级从高到低：

1. **线程封闭**：尽量不共享数据，每个线程使用独立的数据副本，从根源避免竞争，比如每个算法线程独立处理单张图像。

2. **线程安全集合**：共享队列、集合使用`ConcurrentQueue`、`ConcurrentDictionary`等线程安全集合，项目中图像队列就用ConcurrentQueue，自动处理并发安全。

3. 轻量同步

   ：

   - `volatile`修饰状态变量，保证内存可见性，用于简单的启停标志。
   - `Interlocked`原子操作，对数值做原子增减、交换，无锁，性能高，用于计数器、状态位。

4. 锁机制

   ：

   - `lock`关键字：互斥锁，保证同一时间只有一个线程进入代码块，项目中用于共享资源、共享变量的并发控制。
   - `ReaderWriterLockSlim`：读写锁，多读少写场景，允许多个读线程同时进入，写线程独占，比lock性能更好，用于参数配置、配置文件读写。

5. **最佳实践**：细化锁粒度，避免嵌套锁，统一加锁顺序，防止死锁；优先用高级同步工具，避免手写低级同步。

**Q5：如果主线程开启了一个循环采集数据的子线程，主线程要如何终止该子线程？** A：

1. 标准方案：CancellationToken取消令牌

   （项目首选）

   - 定义`CancellationTokenSource`，将Token传入子线程。
   - 子线程循环中通过`token.IsCancellationRequested`判断是否取消，收到取消信号后退出循环，安全释放资源。
   - 主线程调用`cts.Cancel()`发起取消，支持超时取消、联动取消，是.NET官方推荐的标准停止方式。

2. volatile标志位方案

   - 定义`private volatile bool _isRunning = true;`，volatile保证多线程内存可见性。
   - 子线程`while(_isRunning)`执行循环，主线程设置`_isRunning = false`，子线程检测到后退出。
   - 适合简单的常驻线程，项目中早期采集线程用过这种方式。

3. **不推荐方案**：`Thread.Abort()`，强制终止线程，不可控，容易造成资源泄漏、数据损坏，工业项目完全不用。

4. **收尾操作**：终止后调用`thread.Join()`等待线程完全退出，确保资源释放完成，再进行后续操作。

**Q6：什么是委托？** A： 委托是C#中的一种**类型安全的函数指针**，它可以存储方法的引用，包含方法的参数列表、返回值类型。 委托本质是一个类，继承自`MulticastDelegate`，可以绑定一个或多个方法，调用委托时会依次执行绑定的所有方法。

**Q7：C#语言里为什么要设计委托这个特性？** A： 核心是**解耦与扩展性**，具体有四个价值：

1. **实现回调机制**：可以把方法作为参数传递，适合异步回调场景。比如相机采图完成、检测完成，通过委托回调通知业务层，底层采集模块不需要依赖上层业务逻辑。
2. **解耦调用方与实现方**：调用方只知道委托的签名，不需要知道具体的实现方法，符合开闭原则。比如定义设备通讯委托，不同协议的通讯方法都可以绑定，上层业务不用修改。
3. **支持多播调用**：一个委托可以绑定多个方法，一次调用依次执行，适合事件通知场景，比如检测完成后同时触发界面更新、日志记录、结果上传。
4. **支撑事件机制**：事件的底层就是委托，委托是事件的基础，事件是委托的安全封装。

**Q9：设计接口的初衷是什么？为什么要使用接口？** A： 核心是**抽象和解耦**，具体价值：

1. **依赖倒置**：上层业务依赖抽象接口，不依赖具体实现，降低耦合。比如定义`ICamera`接口，海康、巴斯勒相机都实现这个接口，上层业务只调用接口方法，更换相机品牌不用修改业务代码。
2. **多态扩展**：同一接口可以有多个不同实现，新增功能只需要新增实现类，不修改原有代码，符合开闭原则。
3. **规范契约**：接口定义统一的行为规范，不同模块、不同开发人员按照接口约定开发，保证协作一致性。
4. **可测试性**：可以基于接口写模拟实现，方便单元测试，不用依赖真实硬件设备。
5. **多重实现**：C#类可以实现多个接口，突破单继承的限制，灵活组合不同的行为能力。

**Q10：你了解哪些常用的软件设计模式？讲讲MVVM是什么？有没有实际使用过？** A：

2. MVVM即Model-View-ViewModel三层架构

   ：

   - **View（视图层）**：只负责界面展示与用户交互，不包含业务逻辑，通过数据绑定关联ViewModel。
   - **ViewModel（视图模型层）**：连接View和Model的中间层，封装业务逻辑、命令与属性，通过属性变更通知View更新界面。
   - **Model（模型层）**：负责数据模型、业务逻辑、数据访问，不依赖UI。

3. **核心优势**：完全解耦UI和业务逻辑，界面和业务可以独立开发、独立测试，代码复用性、可维护性大幅提升。

4. **实际使用**：WPF项目全部采用MVVM架构开发，基类封装`INotifyPropertyChanged`，实现属性变更通知，配合命令绑定，实现了界面和业务完全分离，后期迭代维护效率提升明显。

Q2：产品定位用到了哪些算法？ A：

1. **模板匹配算法**：核心用VisionPro的PatMax特征匹配算法，基于边缘轮廓特征匹配，输出工件XY坐标与旋转角度，抗光照干扰、稳定性高，是最常用的粗定位算法。
2. **亚像素边缘提取算法**：用于精定位，提取工件边缘、圆孔、直线特征，实现亚像素级精度定位，比整像素定位精度提升一个量级。

4. **仿射变换算法**：九点标定求解的变换矩阵，将图像像素坐标转换为机械世界坐标，是定位落地的核心算法。
5. **旋转中心标定算法**：旋转工位场景下，计算旋转中心坐标，补偿旋转带来的坐标偏移，实现任意角度下的精准定位。

Q3：模板匹配的原理 A：

1. 基础原理：提前制作一张标准模板图像，让模板在待测图像上按步长逐像素滑动，在每个位置计算模板与图像对应区域的相似度（相关系数、灰度差等），相似度最高且超过阈值的位置，就是匹配位置。
2. **PatMax这类高级模板匹配**：不是基于灰度匹配，而是提取模板的边缘轮廓特征、梯度方向，在图像中匹配对应的特征分布，不受光照变化、对比度波动的影响，鲁棒性更强，同时支持旋转、缩放匹配。
3. 匹配输出：最终输出匹配位置的XY坐标、旋转角度、匹配得分，得分越高匹配度越好。

Q4：零件外观检测图像预处理都用了什么？ A： 根据缺陷类型组合使用，常用的有五类：

1. **滤波去噪**：中值滤波去除椒盐噪声、颗粒噪点；高斯滤波平滑整体随机噪声，提升后续检测稳定性。
2. **灰度变换**：灰度拉伸、直方图均衡，增强缺陷与背景的对比度，突出弱缺陷。
3. **背景差分**：采集标准无缺陷背景图，待测图减去背景图，差分后突出差异区域，抑制均匀背景干扰。
4. **形态学处理**：腐蚀、膨胀、开运算、闭运算，去除小噪点，连接断裂的缺陷区域，优化缺陷轮廓。
5. **图像校正与裁剪**：旋转校正工件倾斜，ROI裁剪检测区域，排除无关区域干扰，提升检测速度与准确性。

Q5：误检率过高，怎么查找原因 A： 按照从硬件到软件、从外到内的顺序分层排查：

1. **成像层**：采集实时图像，检查是否过曝/过暗、模糊、反光、杂光，镜头是否脏污，光源亮度是否衰减，打光角度是否偏移。
2. **定位层**：检查定位是否偏移，ROI是否跑偏，导致检测区域错位，把正常区域误判为缺陷。
3. **参数层**：检查检测阈值是否过严，滤波参数、缺陷判定规则（面积、长度、宽度阈值）是否不合理，公差设置过紧。
4. **环境层**：排查现场环境光照变化、产线振动、工件来料差异、批次材料变化。
5. **算法层**：检查预处理是否适配当前来料，缺陷分割算法是否误把正常纹理、色差判定为缺陷。
6. **验证优化**：用误检样本复现问题，定位问题点后针对性优化参数或算法，再用批量样本验证误检率下降情况。

Q6：多线程处理图像，怎么确保相机采图不丢帧 A： 核心是**采集与处理解耦**，采集线程轻量化，不被处理阻塞：

1. **架构解耦**：相机采集线程只做最轻量化操作——接收图像、推入线程安全队列，绝对不在采集回调里运行检测算法，避免阻塞相机采集。
2. **队列缓冲**：用线程安全的环形队列做图像缓冲区，缓存一定数量的图像，应对处理速度的瞬时波动，削峰填谷。
3. **并行处理**：启动多个算法工作线程，并行消费队列中的图像，提升整体处理吞吐，保证处理速度≥采集速度。
4. **策略兜底**：设置队列最大长度，队列满时采用丢帧策略，丢弃最旧的过期帧，优先保证最新帧的采集与处理，避免队列溢出阻塞采集线程。
5. **触发同步**：硬触发/编码器触发模式下，保证触发信号稳定，相机触发响应优先级最高，不受业务逻辑影响。

Q7：使用多线程的过程中图像的内存泄漏会是什么原因？怎么优化？ A： **常见原因**：

1. Bitmap等非托管资源未手动释放，GC回收不及时，频繁创建大图像导致大对象堆内存碎片。
2. 图像队列积压，图像引用一直被持有，无法释放。
3. 事件、委托绑定后未解绑，导致图像对象被引用，无法回收。
4. 界面频繁切换图像，旧图像资源未释放，累积泄漏。

**优化方案**：

1. **资源及时释放**：使用`using`语句管理Bitmap对象，用完自动Dispose；图像处理完成后立即释放非托管资源。
2. **图像内存池**：预分配一批图像缓冲区，循环复用，避免频繁创建销毁大对象，减少GC压力与内存碎片。
3. **队列管控**：限制队列最大长度，及时清理过期图像，避免队列无限积压。
4. **界面优化**：界面图像更新时，先释放旧图像再赋值新图像；降低界面刷新频率，减少图像创建频次。
5. **引用管理**：及时解绑事件、委托，避免对象被意外引用导致无法回收；定期检查大对象堆，定位泄漏点。
