Q2：自动贴标引导系统从 0 到 1 怎么实现？你负责哪部分？ 

A:

1. 项目整体流程：需求评估→样件打光测试→硬件选型（相机、镜头、光源）→视觉算法开发→标定→上位机开发→联调→现场试产→验收。
2. 我负责：视觉方案评估、硬件选型，VisionPro算法开发（PMA定位）、九点标定，C#上位机开发，TCP通信模块开发，视觉偏移计算，和贴标运动控制器对接，输出XY角度补偿值，现场调试。
3. 实现步骤：
   1. 相机采集产品图像，PMA定位产品基准，算出产品相对于标准模板的像素偏移和旋转角度。
   2. 通过九点标定矩阵，把像素偏移转换成世界物理坐标的XY、角度偏差。
   3. 将补偿值通过TCP下发给贴标运动控制器。
   4. 运动机构根据补偿量做纠偏，完成贴标；贴标完成读取到位信号，触发下一次拍照。
   5. 增加日志记录、异常报警、超时处理。

Q3：视觉引导的整体流程是怎样的？

A:

1. 触发拍照：PLC/运动控制器发送到位信号，触发相机采集图像。
2. 定位算法：PMA PatMax模板匹配，找到产品基准特征，得到像素层面XY偏移、旋转角度。
3. 坐标转换：使用九点标定仿射矩阵，把像素偏移转换成世界机械坐标的物理偏移。
4. 补偿下发：将XY偏移、角度补偿值发给机器人/运动控制器。
5. 机构纠偏：运动机构执行补偿移动，完成抓取/贴标/装配。
6. 反馈确认：机构运动完成后回传到位信号，开始下一轮循环；定位失败输出NG报警。

Q4：九点标定是为了什么？

 A:

1. 建立图像像素坐标系与机械世界坐标系之间的仿射变换关系。
2. 实现像素坐标和物理坐标互相转换，计算真实物理偏移量。
3. 修正镜头畸变、相机安装倾斜带来的坐标误差。
4. 视觉定位得到的偏移量，换算成机械可识别的补偿值，用于视觉引导纠偏。

Q5：贴标偏差值是怎么计算出来的？

 A:

1. 训练标准模板：产品在标准位置时采集图像，训练PMA模板，此时的位置为基准零点。
2. 产品来料拍照，PMA匹配得到当前工件相对于模板的像素X偏移、像素Y偏移、旋转角度。
3. 调用九点标定仿射变换矩阵，将像素偏移转换为世界坐标系下物理XY偏差和角度偏差。
4. 该物理XY、角度，就是贴标机构需要补偿的偏差值。
5. 增加滤波，对连续多帧结果做均值过滤，减少噪声带来的抖动。

Q6：旋转中心怎么找？找到后用来干什么？

 A:

1. 寻找旋转中心：  方式1：标定阶段，将工件绕自身旋转中心旋转多个角度采集标定点，通过旋转标定计算出工件在世界坐标系下的旋转中心。  方式2：PMA定位得到工件基准特征中心，直接作为工件旋转中心。
2. 作用：工件旋转补偿时，必须以工件自身旋转中心做旋转计算，而不是以图像原点旋转；否则角度补偿会附带额外XY偏移，贴标位置出现偏差。

Q7：相机选型靠哪几个要素？

 A:

1. 视场FOV：工件最大外形尺寸，预留余量。
2. 检测精度：最小特征尺寸，确定所需像素当量。
3. 运动状态：静止定拍选卷帘；高速运动、飞拍选全局快门。
4. 产线节拍：确定相机帧率、曝光时间。
5. 接口类型：GigE/USB3，考虑图像传输带宽。
6. 工作环境：温度、防尘；反光、高湿环境做防护。

Q8：镜头选型要考虑哪些因素？

 A:

1. 靶面尺寸：镜头靶面≥相机靶面，避免暗角。
2. 焦距：根据工作距离、视场、靶面计算焦距。
3. 分辨率：镜头光学分辨率要满足像素精度要求。
4. 畸变：尺寸测量/引导优先低畸变；高精度测量选用远心镜头。
5. 景深：工件表面高度差，保证全范围清晰。
6. 安装接口：C口/CS口，匹配相机。
7. 工作距离：满足现场机械安装空间。

Q9：WinForm、WPF 都在项目里用过吗？

Q10：TCP 通讯你是客户端还是服务端？怎么判断连接状态？

 A:

1. 两种都写过。上位机作为TCP客户端，去连接PLC/运动控制器服务端；少数场景上位机作为服务端，等待外部设备接入。
2. 判断连接状态：
   1. Socket自带状态判断，但不能只靠这个，网络断连底层不会立刻感知。
   2. 增加心跳包机制，定时收发心跳报文。
   3. 设置收发超时；连续多次心跳无应答，判定断开，自动触发重连。
   4. 捕获通信异常，在异常回调中标记连接断开。

Q11：心跳是单线程还是多线程？会卡 UI 吗？

 A:

1. 心跳放在独立后台线程/Task循环里执行，不属于UI线程。
2. 不会卡住UI：心跳收发、超时判断都在后台；UI只接收连接状态通知，用委托回调更新界面状态。
3. 注意：心跳间隔不要太短；断连后的重连逻辑也放在后台，避免阻塞。

Q13：VisionPro、VisionMaster、Halcon 有什么区别？

 A:

1. VisionPro（康耐视）：可视化拖拽工具链，QuickBuild快速调试，脚本扩展强；上手快，稳定，适合快速落地2D定位、测量、外观项目；适合产线项目交付。
2. VisionMaster（海康）：国产平台，集成2D、3D、深度学习，可视化编程，配套海康相机生态好，国内技术支持方便。
3. Halcon：底层算子库，纯代码开发，算法自由度最高，算子极其丰富；适合复杂定制算法；学习成本高，开发周期更长。

Q14：高精度缺陷检测，用 VisionPro 怎么做？

 A:

1. 成像优先：做好光源选型打光，最大化缺陷与背景对比度；选用合适相机镜头，保证足够像素当量。
2. 预处理：滤波降噪，保留缺陷边缘。
3. 定位：PMA稳定定位工件，裁剪ROI，排除无关背景干扰。
4. 缺陷提取：Blob、灰度分析、差分工具提取缺陷区域。
5. 阈值优化：基于OK/NG样件调试阈值，平衡漏检、误检。
6. 标定：九点标定保证尺寸精度；多帧结果过滤降噪。
7. 复杂低对比度缺陷，可搭配AI工具做缺陷分类。

Q15：项目中常用哪些通讯协议？

 A:

1. TCP/IP：上位机和运动控制器、PLC通讯，下发视觉补偿。
2. RS232/RS485串口：传感器、仪表、老款控制器。
3. Modbus RTU（串口）、Modbus TCP：读写PLC寄存器，IO交互。
4. 相机：GigE Vision协议采集图像。

Q16：Modbus 主站是服务器还是客户端？

 A:

1. Modbus主站 = 客户端（Client），主动发起请求，去读写从站寄存器。
2. Modbus从站 = 服务端（Server），被动等待主站请求，响应数据。
3. 我们上位机做Modbus主站，主动读写PLC的寄存器。

Q17：你做项目的完整流程（从 0 到 1）是什么？

A:

1. 需求对接：确认检测内容、精度、节拍、漏检误检指标，收集OK/NG样件。
2. 方案评估：样件打光测试，评估算法可行性，识别项目风险；硬件选型，输出方案。
3. 硬件采购、机架工装制作。
4. 算法开发：VisionPro工具调试、标定，离线样件测试。
5. 上位机开发：框架、通信、数据存储、界面、日志。
6. 现场装机联调：相机光源安装、标定，和PLC/运动控制器联调。
7. 小批量试产：迭代阈值优化，统计良率、漏检误检。
8. 稳定性测试，客户验收，交付文档、培训。

## 12组

Q1：计算基准平面相对高度差是怎么去计算的

 A:

1. 拿到3D线扫输出的高度图，先在图像上框选基准平面ROI区域。
2. 在基准ROI内采样大量高度点，拟合平面方程 z = a*x + b*y + c。
3. 平面拟合完成后，这个平面就是基准平面。
4. 对目标检测区域内每一个高度点，用该点的实际高度 z_target 减去拟合平面在该XY位置对应的基准高度 z_plane。
5. 得到差值 Δz = z_target − z_plane，这个Δz就是该点相对基准平面的高度差。
6. 根据高度差阈值判断该位置是凸起还是凹陷缺陷。

Q2：基准平面选点有什么讲究吗，还是说随便选

 A:

1. 不能随便选。
2. 选点要求：
   1. 选取的区域必须是真实平整、无缺陷、无毛刺的工件基准面，不能包含划痕、凹坑、溢胶。
   2. ROI尽量分布均匀，多点采样，覆盖足够大的平面范围，避免局部小区域带来拟合偏差。
   3. 避开边缘、台阶、反光噪点区域，噪点会严重影响平面拟合结果。
   4. 基准区域尽量和待测区域在同一工件平面层级，减少曲面带来的误差。
   5. 如果工件存在倾斜，足够多且分布均匀的采样点才能正确拟合平面倾角。

Q3：想找到图像的边缘信息，比如说想检测一条划痕，你会怎么做 

A:

1. 预处理：先做滤波降噪（高斯/中值滤波），去除图像噪声，保留边缘。
2. 边缘提取：使用边缘算子，VisionPro里可以用CogEdgeTool提取边缘；也可以用灰度差分的方式，划痕和基材存在灰度差，提取轮廓。
3. 阈值分割：对边缘图做阈值，筛选有效边缘，过滤细小噪声伪边缘。
4. 特征筛选：通过Blob工具，筛选长度、宽度、面积、长宽比，根据划痕细长的特征过滤掉点状噪点。
5. 坐标提取：得到划痕的像素坐标，结合标定转换为物理尺寸，判断划痕长度、宽度是否超差。
6. 优化：先PMA定位工件ROI，减少背景干扰；打光优化提升划痕对比度，这是前提。

Q4：中值滤波相对于高斯滤波有什么好处吗，中值滤波和高斯滤波分别应用在什么场景 

A:

1. 中值滤波优势：属于非线性滤波，可以很好消除椒盐噪声，同时边缘保留效果更好，不容易把边缘模糊化；高斯滤波会平滑边缘，边缘容易变虚。
2. 中值滤波场景：图像存在椒盐噪点、散点脏污，需要保留边缘轮廓的时候，比如表面颗粒噪声工件划痕检测。
3. 高斯滤波场景：高斯是线性平滑滤波，用来抑制高斯噪声，对整幅图像柔和降噪；适合噪声比较均匀，不要求强边缘保留，只是平滑图像、减少灰度突变，为后续边缘提取做预处理。

Q5：什么是椒盐噪声，特征是什么 

A:

1. 椒盐噪声：图像随机出现黑白散点噪声，像撒上盐和胡椒。盐是白色亮点（灰度255），胡椒是黑色黑点（灰度0）。
2. 特征：
   1. 孤立的单点，随机分布。
   2. 灰度直接跳到最大值或者最小值，和周围像素灰度差异巨大。
   3. 成因：相机信号脉冲干扰、镜头灰尘、强光尖峰干扰。
   4. 处理：中值滤波对椒盐噪声抑制效果最好；高斯滤波效果很差。

Q6：双缓冲的原理是什么

 A:

1. 双缓冲核心：开辟两块内存画布，前台缓冲区和后台缓冲区。
2. 前台缓冲区：直接渲染显示在屏幕上，用户可见。
3. 后台缓冲区：程序在后台内存绘制图像、标注框、文字，所有绘制操作都在后台完成。
4. 绘制完成后，一次性把后台画布整体交换到前台显示。
5. 好处：避免一边绘图一边刷新界面造成闪烁；不会出现半画完的残缺图像。
6. 应用：Winform/WPF绘制图像、缺陷标注，上位机图像显示控件经常用到双缓冲。

## 14组

Q1：视觉上侧重于引导还是检测？

 A:

1. 两类项目都做过，检测项目会更多；视觉引导属于另一大类，像自动贴标纠偏项目就是引导类。
2. 缺陷检测：重点是检出划痕、脏污、缺料等缺陷，判断OK/NG，输出缺陷位置、尺寸；对算法稳定性、漏检误检指标要求高。
3. 视觉引导：重点是精准计算工件相对基准的XY偏移与旋转角度，输出补偿量给到运动机构，对坐标转换、标定精度要求高。
4. 个人能力两者都覆盖，缺陷检测项目经验更多，引导项目熟悉从标定到补偿下发整套流程。

Q2：简述一下视觉引导的流程？

 A:

1. 触发拍照：运动机构运行到位，IO信号触发相机采集图像。
2. 特征定位：PMA模板匹配寻找工件基准特征，算出工件相对于标准模板的像素XY偏移、旋转角度。
3. 坐标转换：利用九点标定的仿射矩阵，把像素偏移换算成机械世界坐标系下的物理偏移量。
4. 补偿计算：基于工件旋转中心，计算纠偏所需XY、角度补偿值。
5. 下发补偿：通过TCP/Modbus把补偿值发给运动控制器或机器人。
6. 机构执行纠偏，完成贴标/抓取；执行完成回传到位信号，进入下一轮拍照。
7. 异常处理：定位失败直接报警，停止流程，记录日志。

Q3：说一下VisionPro中视觉引导需要先后用到哪些工具？

 A:

1. CogPMAlignTool（PMA，PatMax模板匹配）：核心定位工具，训练模板，获取工件偏移、角度。
2. CogCalibNPointToNPointTool（九点标定工具）：生成仿射变换矩阵，像素坐标转世界坐标。
3. CogTransform2DLinear：坐标变换，完成像素偏移到机械偏移换算。
4. 可选：CogFindCircleTool/CogFindLineTool，当工件没有合适的PatMax特征时，用圆、边缘作为基准特征定位。
5. 脚本工具（CogScript）：高级脚本，计算旋转中心补偿、结果判断、报文组装。

Q4：用过抓圆抓边这些工具吗？

 A:

1. 用过，对应就是CogFindCircleTool抓圆、CogFindLineTool抓边。
2. 使用场景：工件有圆孔、外圆特征时，用FindCircle提取圆心做定位基准；工件有直边特征，用FindLine提取直线边缘，以直线位置、角度做基准。
3. 相比PMA，圆和直线工具适合特征简单、边缘清晰的工件；抗光照变化、轻微形变能力弱于PatMax。
4. 实际项目中，经常搭配PMA使用，辅助验证基准位置是否可靠。

Q5：用到了哪些图像算法？

 A:

1. 定位类：PatMax模板匹配（PMA）、圆查找、直线查找、Blob重心定位。
2. 预处理算法：高斯滤波、中值滤波，图像增强，直方图拉伸。
3. 边缘算法：边缘提取，边缘打分筛选，提取边缘位置与对比度。
4. 坐标计算：仿射变换，坐标平移、旋转，点/线/矩形的坐标映射。
5. 阈值分割：灰度阈值，Blob连通域分析，提取缺陷区域。
6. 拟合算法：平面拟合（3D）、直线拟合、圆拟合。
7. 后处理：结果滤波，多帧均值平滑，过滤单次随机噪声带来的偏移抖动。

## 15组 

Q1：数据存储值类型和引用类型怎么选择？

 A:

1. **值类型（struct）**：数据量小、结构简单，如坐标点、像素当量、尺寸、角度；数据独立，不需要多地方共享，拷贝开销很小；放在栈上访问更快。

2. 引用类型（class）

   ：数据量大、成员多，需要在多处共享同一个实例对象；需要继承、多态；需要频繁传递对象，不想拷贝完整数据；对象生命周期较长。

   > 简单记：小、轻、独立 → struct；复杂、需要共享/继承 → class。

Q2：从数据库中取出一个数模型，怎么判断用class还是用结构体struct？

 A:

1. 如果模型字段多、对象要在多处代码共享传递，优先 **class**。ORM框架（如Dapper、EF）对class支持更好。
2. 如果模型字段很少（2~4个数值），只是单纯承载一组独立数据，不需要共享、继承，可考虑struct。
3. 数据库实体一般**推荐class**。struct是值类型，每次赋值都会完整拷贝全部字段；实体字段多的时候拷贝开销很大，容易造成性能损耗。

Q3：class和struct大小是有区别的，这个原因是什么？ 

A:

1. struct是**值类型**，存储在栈（或者装箱后堆上），占用内存就是所有成员大小之和，加上少量内存对齐填充。
2. class是**引用类型**，实例分配在堆上；变量本身只是一个**引用指针（8字节64位）**。对象本身除了成员数据，还额外附带对象头（标记、类型指针）。
3. 区别根源：class变量存的是地址；struct变量直接存全部数据。

Q4：在一个项目中，大量使用引用类型，引用类型的对象也比较大，那么它会引发什么样的问题？

 A:

1. **堆内存占用高**，大量大对象会进入大对象堆LOH，LOH默认不压缩，容易造成内存碎片。
2. GC频繁：大量对象创建销毁，GC频繁触发，出现GC停顿，上位机卡顿，影响视觉算法实时性。
3. 内存泄漏：对象被事件、委托长期引用，无法回收，内存持续上涨。
4. 共享对象带来**线程安全问题**，多线程同时修改同一个引用对象，会出现数据错乱。

Q5：值类型和引用类型传的分别是什么？

 A:

1. 值类型默认传**值副本**：方法内部拿到一份拷贝，方法内修改副本不会影响外部原变量。加`ref/out`才传递变量地址。
2. 引用类型默认传**引用的副本**：拷贝的是对象地址，方法内通过这个地址修改对象里面的字段，会影响外部原对象；但如果给引用变量重新赋值（new新对象），不会影响外部。

Q6：class和struct有什么区别？ 

A:

1. class：引用类型，堆分配；支持继承、无参构造函数可自定义；可以为null。
2. struct：值类型，默认栈分配；**不能继承类**，只能实现接口；不能定义无参构造（C#10前）；不能为null（可空除外`struct?`）。
3. 拷贝：class拷贝引用地址；struct拷贝全部成员。
4. 使用场景：复杂业务模型，多态继承用class；轻量小型数据载体（点、坐标）用struct。

Q7：字符串是值类型还是引用类型？为什么？ 

A:

1. string是**引用类型**，继承自`object`，数据存堆。
2. 特殊点：string具备**不可变性（immutable）**。一旦字符串创建就不能修改；任何修改、拼接操作都会生成新字符串对象。
3. 字符串池（string pool）：CLR做字符串常量池优化，相同字面量字符串复用同一个实例，节省内存。

Q8：字符串的拼接有哪些方法？ 

A:

1. `+` 运算符：简单少量拼接，底层编译器会优化。多次循环拼接不推荐，每次都会生成新string。
2. `string.Format()` / 字符串插值`$""`：格式化拼接。
3. `StringBuilder`：循环大量拼接首选，内部可变字符缓冲区，减少堆上新对象创建。
4. `string.Join()`：数组/集合元素拼接，非常适合把集合用分隔符连成字符串。

Q9：怎么判断字符串是否相等？怎么判断一个list是否相等？

 A:

1. 字符串相等：
   - `==`：C# string重载了==，比较内容；
   - `string.Equals()`，可指定忽略大小写`StringComparison`，推荐用这个，可控。
2. List：
   - `==` 只判断是不是同一个引用实例，**不对比内部元素**。
   - 需要判断元素全部相等：自己循环逐个对比元素；或者使用LINQ `SequenceEqual()`。

Q10：接口类和抽象类的区别？在什么时候使用接口类？在什么时候使用抽象类？

 A:

1. 区别：
   - 抽象类（abstract class）：可以有字段、属性、实现好的方法、抽象方法；一个类只能继承一个抽象类。
   - 接口（interface）：默认没有字段，只能定义契约（方法、属性、事件）；C#8+可以写默认实现；一个类可以实现多个接口。
2. 抽象类：多个子类有大量**共用代码**，抽取公共逻辑，保留部分方法让子类重写。
3. 接口：定义能力契约，无关的多个类都拥有同一个能力；需要多契约组合时使用。例：`IDisposable`、自定义`ICanSave`保存接口。

Q11：什么是委托和事件？有了委托为什么还要用事件？

 A:

1. 委托：类型安全的方法指针，可以保存一个或多个方法引用，可直接调用、赋值覆盖。
2. 事件：是委托的一层封装，**只允许在类内部触发**。外部只能`+=`订阅、`-=`取消订阅。
3. 为什么要事件：
   - 安全性：防止外部代码直接`=`覆盖掉所有回调方法；防止外部直接Invoke触发。
   - 语义：事件表达“通知”，比如图像采集完成、收到报文；委托更偏向方法参数传递。

Q12：Event可以外部调用吗？

 A: **不可以**。事件只能在定义这个事件的类内部调用（Invoke）。外部只能订阅`+=`和取消订阅`-=`，不能直接触发。

Q13：try-catch-finally的执行顺序？在try和catch中分别使用return，它们的表现有什么不一样？

 A:

1. 顺序：先执行try代码块 → 出现异常进入catch → **无论是否异常、是否return，finally一定会执行**。
2. try里面return：先执行return前逻辑，然后跳去执行finally，最后才return返回。
3. catch里面return：捕获异常后执行catch内部逻辑，同样先执行finally，再return。
4. 注意：finally里面如果写return，会覆盖try/catch的返回值，不推荐。

Q14：泛型是什么？为什么要用泛型？ 

A:

1. 泛型：模板式代码，定义类/方法/接口时不指定具体类型，使用的时候传入类型参数`<T>`。
2. 好处：
   - 类型安全：编译期类型检查，避免类型转换错误。
   - 避免装箱拆箱，提升性能。
   - 一份代码复用，不用为不同类型写多个重载版本。  例子：`List<T>、Dictionary<TKey,TValue>`。

Q15：数据库中分页怎么写？

 A: MySQL：

```
SELECT * FROM table WHERE 条件 ORDER BY id LIMIT 页码偏移量,每页行数;
```

SQL Server（2012+）：

```
SELECT * FROM table ORDER BY id OFFSET 偏移行数 ROWS FETCH NEXT 页行数 ROWS ONLY;
```

> 注意：大偏移量直接LIMIT/OFFSET性能差，大数据量推荐**主键书签分页**（where id>上一页最大id）。

Q16：数据库查询起来比较慢，有哪些办法可以优化和排查？怎么分析SQL语句哪里慢？

 A:

排查手段

1. `EXPLAIN`（MySQL）/执行计划（SQL Server），看索引有没有命中、有没有全表扫描、是否存在文件排序、临时表。
2. 查看慢查询日志，捕获耗时SQL。
3. 监控数据库连接、CPU、IO。

优化方案

1. 加索引：WHERE、JOIN、ORDER BY字段建立合适索引；避免索引失效（函数、隐式转换、模糊查询开头%）。
2. 减少返回字段：不要`select *`，只查需要的列。
3. 减少结果集：提前过滤WHERE条件。
4. 优化分页：大偏移量不要直接OFFSET。
5. 避免大事务、锁等待。
6. 合理分表，数据量巨大做分库分表。
