## 6组

Q1：大图拼接后如何把里面的小图缺陷分别标注出来 

A:

1. 采集阶段：每一张原始小图采集时，记录当前载具的世界坐标（XY+角度）以及这张小图在全局空间中的位置范围。
2. 缺陷检测：在单张小图内完成缺陷检测，得到缺陷在该小图上的像素坐标。
3. 坐标转换：利用单图标定矩阵，将缺陷像素坐标转换为**世界坐标系下的物理坐标**。
4. 大图拼接：把所有小图根据各自世界坐标，拼接生成一张完整全景大图，同时记录大图本身的全局坐标映射关系。
5. 缺陷投影标注：将缺陷的世界坐标，反向换算到大拼接图的像素坐标；在大图对应的像素位置绘制框、点进行标注。
6. 关联溯源：保留缺陷归属的原始小图编号，点击大图上标注的缺陷，可快速切回对应的原始小图查看细节。

Q2：飞拍如何让曝光与相机同步触发 

A:

1. 飞拍即运动中拍照，载具不停顿，核心保证**运动位置、触发信号、相机曝光三者同步**。
2. 常用方案：编码器触发。运动轴挂载编码器，运动控制器实时读取脉冲；当移动到预设位置，运动控制卡输出硬件触发信号给相机。
3. 信号链路：编码器脉冲 → 运动控制卡比较位置 → 硬件IO触发相机采集。
4. 时序要点：
   1. 使用硬件触发，不使用软件触发，软件有延迟抖动，飞拍会出现位置偏移。
   2. 提前设置相机曝光时间，触发信号到达后相机立即开始曝光。
   3. 提前做触发延时校准，补偿信号传输、相机内部响应延迟。
   4. 控制曝光时间尽可能短，减少运动模糊。
5. 同步校验：连续采集图像，验证产品在图像中的位置是否稳定，无漂移。

Q3：运动选项卡有没有使用过 有什么品牌

 A:

1. 使用过VisionPro QuickBuild里的运动选项卡，用来对接运动控制器，实现视觉引导运动、点位移动。
2. 支持的品牌：
   1. 康耐视自带：Cognex Motion（原生）
   2. 固高（Googol）、雷赛、研华运动控制卡
   3. 还有部分第三方运动控制器，可通过TCP/Modbus对接。
3. 作用：在QuickBuild内直接下发点位，接收视觉PMA算出的XY偏移、角度，自动补偿运动坐标；可以直接调试视觉纠偏，不用写上位机代码。
4. 局限：项目正式交付时一般自己在上位机写通信对接，灵活性更高，方便做异常处理、日志和界面配置。

Q4：232通信是干什么的 

A:

1. RS232是一种早期串行异步通信接口，用于设备之间短距离点对点数据传输。
2. 用途：上位机和外部设备之间收发指令、状态、报文。比如和PLC、传感器、条码枪、小型仪表、运动控制器通讯。
3. 特点：点对点通信，不能多设备并联；传输距离短，一般十几米；速率不高；电平是正负电压。
4. 对比：工业现场更多改用RS485（支持多节点、距离更远）；RS232现在很多时候需要USB转232模块接电脑。
5. 项目中用法：C# SerialPort类读写报文，增加校验、超时、重连机制，实现指令下发与状态读取。

Q1：VisionPro中求取平均灰度用哪个工具

 A:

1. CogHistogramTool（直方图工具）最常用，运行后可以读取均值属性得到区域内平均灰度。
2. 也可以用CogBlobTool，Blob分析结果里同样可以获取Blob区域平均灰度。
3. 简单脚本/高级脚本：拿到图像区域后，代码遍历像素计算灰度均值，适合自定义ROI。

Q2：灰度直方图含义 

A:

1. 灰度直方图，统计图像中每一个灰度等级（0~255）对应的像素数量。
2. 横轴代表灰度值，0为纯黑，255为纯白；纵轴代表该灰度下像素点个数。
3. 作用：判断图像整体明暗、对比度；观察灰度分布，辅助设置二值化阈值，判断缺陷和背景灰度差异。
4. 直方图集中在窄区间代表图像对比度差；分布跨度大代表对比度较好。

Q3：VisionPro中有哪些方法可以增强图像对比度 

A:

1. CogContrastTool：对比度调整工具，直接拉伸灰度范围。
2. CogEqualizeTool：直方图均衡化，扩展图像动态范围，提升弱对比度细节。
3. CogLookupTool：查找表工具，自定义灰度映射曲线，选择性拉伸感兴趣灰度区间。
4. 滤波预处理：CogSharpnessTool锐化，增强边缘灰度差。
5. 脚本：高级脚本手动做灰度线性映射，自定义对比度增强逻辑。

Q4：VisionPro中FindLine和FindCircle有一个计分函数的功能有三个函数，分别有什么含义，筛选逻辑是什么

 A:

1. Contrast（对比度得分）：边缘剖面明暗灰度差值，只有大于对比度阈值才会被判定为候选边缘。得分越高代表边缘明暗差异越明显，边缘越可靠。
2. Position（位置得分）：候选边缘位置和预期目标位置的接近程度。离预期搜索中心线越近，得分越高；偏离越远得分越低。
3. PositionNeg（负向位置得分）：和Position相反，用来过滤在预期位置反方向的候选边缘，抑制反向虚假边缘。
4. 筛选逻辑：三个得分加权综合，总分高于设定分数阈值，工具才保留这条线/圆；低于阈值直接舍弃，过滤噪声、伪边缘。

Q5：高级脚本中定义一个彩色图像，他的关键字是什么 

A:

1. 类型关键字：`CogColorImage`。
2. 示例：`CogColorImage colorImg;`
3. 注意区分灰度图`CogImage8Grey`。

Q6：高级脚本中定义两个坐标系之间的转换关系，定义的变量类型是什么？

 A:

1. 使用`CogCoordinateTransformation`，最常用子类是`CogAffineTransform`（仿射变换，九点标定结果就是仿射变换）。
2. 仿射变换可以完成平移、旋转、缩放、剪切，实现像素坐标与世界坐标互相转换。

Q7：获取了变量类型之后怎么去映射一条线或矩形

 A:

1. 拿到CogAffineTransform坐标变换对象。
2. 定义原始图形：CogLineSegment、CogRectangle。
3. 使用Transform方法：调用图形对象的`Transform()`方法，传入变换对象，生成新坐标系下对应的线/矩形。
4. 示例：`CogLineSegment newLine = oldLine.Transform(affineTrans);`
5. 反向转换调用InverseTransform，世界坐标转回图像像素坐标。

Q8：九点标定用哪个工具？怎么评判标注结果的好坏，工具本身有没有评判标注结果的工具 

A:

1. 九点标定工具：`CogCalibNPointToNPointTool`（多点标定工具）。
2. 评判标定好坏：主要看重投影误差（RMS误差，均方根误差），单位一般是像素。RMS越小，标定精度越高。
3. 工具自带评判：工具运行完成后，输出RMS误差，查看每个标定点的残差；个别点残差很大说明该标定点识别出错，需要剔除重采。
4. 辅助验证：取不在标定点内的测试点，用标定矩阵转换坐标，对比实测物理坐标误差。

Q9：C#中什么情况用多线程

 A:

1. 耗时计算：图像算法、大量数据运算，避免阻塞UI主线程。
2. IO等待：串口、TCP通信、数据库读写、文件保存，IO会等待，放到后台线程不卡住界面。
3. 并发任务：同时采集多相机图像，并行处理多个算法任务，提升整体产线节拍。
4. 独立循环任务：持续监听PLC信号、轮询设备状态，单独线程循环。
5. 注意：UI控件不能跨线程直接操作，需要委托回调。

Q10：有多个线程需要访问同一个变量，怎么确保线程安全性

 A:

1. lock锁：访问共享变量代码块加lock，同一时间只允许一个线程进入临界区。
2. 读写分离场景：ReaderWriterLockSlim读写锁，读可并发，写互斥。
3. 原子类型：简单数值变量可用Interlocked类做原子操作，减少锁开销。
4. 避免共享：尽量不共用变量，每个线程使用局部变量，从根源减少竞争。
5. volatile关键字：修饰布尔、状态标记变量，防止CPU指令重排造成读取旧缓存。

Q11：什么是委托 

A:

1. 委托是C#里面类型安全的方法指针，可以保存一个或者多个方法的引用。
2. 委托可以当做参数传递，实现回调。
3. 可以绑定静态方法或者实例方法，支持多播委托绑定多个方法，一次调用执行全部绑定方法。
4. 典型场景：跨线程UI更新、事件回调、消息通知。

Q12：什么是泛型 

A:

1. 泛型是一种代码模板，在定义类、方法、接口的时候不指定具体数据类型，使用的时候再传入类型。
2. 好处：一份代码可以适配多种数据类型，不用重复写多个重载版本；编译时类型检查，避免装箱拆箱，提升性能。
3. 例子：List、Dictionary<TKey,TValue>，T就是泛型参数。

Q2：瑕疵检测用的传统方式吗

 A:

1. 大部分场景优先传统视觉算法，稳定性高、速度可控，适合纹理简单、缺陷特征清晰的瑕疵，比如划痕、脏污、缺料、边缘崩损。
2. 局限性：产品背景纹理复杂、缺陷形态不固定、低对比度微弱瑕疵，传统算法很难区分缺陷与背景噪声，漏检误检很难压下去。
3. 方案组合：传统算法负责产品定位、ROI裁剪、预处理；复杂缺陷场景搭配深度学习模型做缺陷分类/分割，两者结合使用。

Q3：做过最复杂的关于引导类的项目用到了几个相机 

A:

1. 最多用到4个相机的视觉引导项目。
2. 项目场景：工件尺寸大，单相机视野无法覆盖，多相机同步采集，九点标定统一到同一世界坐标系。
3. 流程：4台相机分别定位工件不同特征，汇总所有特征坐标，计算工件整体XY偏移与旋转角度，输出补偿量给到运动控制器完成纠偏。
4. 难点：多相机坐标统一、相机触发同步、控制总算法节拍，保证所有相机采集完成后再做联合计算。

Q4：飞拍跟传统定拍的区别

 A:

1. 定拍：载具运动到指定位置，停止运动，等待稳定后再触发相机拍照。优点：成像清晰，无运动模糊，触发简单；缺点：需要启停，占用产线时间，节拍慢。
2. 飞拍：载具持续运动不停止，依靠编码器位置触发相机抓拍。优点：无需停顿，产线节拍高；缺点：对曝光时间、信号同步要求高，曝光过长会产生运动模糊。
3. 触发方式：定拍常用软件IO触发；飞拍必须使用编码器硬件触发，保证位置同步。
4. 应用场景：定拍适合精度要求极高、节拍宽松项目；飞拍用于高速流水线，对产线效率要求高。

Q5：有没有用过全局相机 

A:

1. 用过全局快门相机。
2. 全局快门相机：整幅图像所有像素同时曝光，拍摄运动物体不会产生果冻效应，不会出现图像倾斜变形。
3. 对比卷帘快门：卷帘快门逐行曝光，高速运动物体容易畸变。
4. 使用场景：飞拍、高速运动工件拍照，优先选用全局快门相机；缺点同分辨率下成本更高。

Q6：有没有用过3d扫描仪 

A:

1. 接触过3D线激光扫描仪项目。
2. 主要用来采集工件高度轮廓，检测翘曲、共面度、溢胶、凹陷凸起、厚度测量。
3. 工作方式：工件移动，激光扫描生成高度图；3D高度数据配合2D图像联合检测。
4. 局限：高反光工件容易产生噪点；细小平面划痕3D不敏感，一般搭配2D视觉一起检测。

Q7：是否做过售前，项目的评估

 A:

1. 参与过项目前期评估、售前技术对接。
2. 评估内容：
   1. 需求确认：检测内容、最小缺陷尺寸、精度要求、产线节拍、允许漏检误检率。
   2. 样件评估：拿客户样件做打光测试，验证成像可行性，判断传统算法还是需要深度学习。
   3. 硬件评估：相机、镜头、光源、运动、IO、通讯方案选型，估算成本。
   4. 风险评估：评估难点，比如高反光、微小缺陷、高速飞拍等潜在风险点，提前告知客户边界。
   5. 工期评估：算法开发、上位机开发、现场调试周期预估。
3. 输出评估结论：能否实现，方案、预估成本、项目风险。

## 9组

Q1：项目里有 3D，用的是激光线扫、双目还是结构光？

 A:

1. 项目使用**激光线扫3D相机**。
2. 原理：激光线投射到工件表面，相机采集激光线形变，计算高度信息。
3. 优势：高度精度稳定，适合连续移动工件扫描，非常适合流水线产品轮廓、高度类缺陷检测。
4. 双目、面结构光在现场也了解过，双目容易受环境光干扰；面结构光适合静态工件，不适合高速连续传送带场景。

Q2：3D 用的是哪家的相机？

 A:

1. 项目使用的是国内厂商的激光线扫相机。
2. 配套SDK获取高度图、轮廓数据，上位机C#对接SDK，拿到高度图像后结合VisionPro做2D+3D联合检测。

Q3：产品是移动的还是静止的？ 

A:

1. 产品在传送带上**连续移动**。
2. 线扫相机配合编码器同步采集，工件持续运动，不需要停稳拍照，属于飞扫模式，满足产线节拍。

Q4：传送带拍照是怎么触发的？

 A:

1. 采用**编码器硬件触发**。
2. 编码器安装在传送带滚轮上，传送带移动同步输出脉冲。
3. 脉冲接入线扫相机，每移动固定距离，触发一次激光线采集，保证采样点空间间距均匀，不会因为传送带速度波动造成图像拉伸变形。
4. 前端增加光电传感器，工件到达感应位置，启动编码器采集，工件离开则停止采集。

Q5：你的标定是怎么标定的？标了几个点？ 

A:

1. 2D视觉部分使用**九点标定（CogCalibNPointToNPointTool）**。
2. 总共采集9组标定点，获取图像像素坐标和机械世界坐标，生成仿射变换矩阵，完成像素到物理坐标转换。
3. 3D线扫相机单独做高度标定，校正高度方向精度。
4. 如果是手眼项目，额外做手眼标定。

Q6：实际硬件是怎么去做标定的？顺序是什么？

 A:

1. 准备：把标定板固定在工装载具上，保证标定板平面和工件平面保持同一高度。
2. 硬件复位：移动机构回原点。
3. 采集第1组：移动标定板到视野中心，拍照，记录当前机械坐标。
4. 依次移动载具，将标定板移动到视野内8个不同位置（上下左右及四个对角），一共采集9组图像+对应的机械坐标。
5. VisionPro工具识别每张标定板圆点，提取像素坐标，录入对应的机械坐标。
6. 运行标定工具，生成仿射变换矩阵，查看RMS残差，判断标定是否合格。
7. 验证：取一个不在9个标定点内的验证点，移动到视野拍照，对比换算后的物理坐标和实际机械坐标误差。

Q7：像素坐标和机械坐标是怎么获取的？

 A:

1. 像素坐标：VisionPro算法识别标定板圆点，工具自动提取圆点在图像里的像素XY。
2. 机械坐标：运动控制器/传送带系统读取当前载具编码器或者伺服轴的位置，上位机同步读取当前机械XY，作为世界坐标。
3. 一一绑定：每一张标定图像对应的像素点集合，绑定同一时刻读取到的机械坐标，送入标定工具计算变换矩阵。

Q8：基准点是用什么做基准？ 

A:

1. 以**工装载具的机械坐标系原点**作为世界基准。
2. 标定板放在载具上，所有标定点的机械坐标都基于载具机械原点。
3. 工件输送到视野内，所有检测得到的缺陷坐标都转换到该载具机械坐标系，方便给到运动控制器或者PLC。

Q9：用的是几轴机器人？带不带旋转？ 

A:

1. 项目使用**六轴机器人，带旋转轴**。
2. 机器人末端可以旋转，视觉算出工件XY偏移和角度，机器人接收补偿量，完成位置和角度纠偏。

Q10：手眼标定是手在眼上（EyeInHand）还是手在眼下（EyeToHand）？

 A:

1. 使用EyeToHand（眼在手外）。
2. 相机固定安装在机架上不动，机器人抓取工件移动到相机视野拍照。
3. 优点：相机固定，视野稳定，相机不需要跟随机器人运动，不会有相机震动影响成像。
4. EyeInHand是相机装在机器人末端，随机器人一起移动，适合需要近距离多角度拍摄的场景，这个项目没有采用。

Q11：锂电池划痕检测用的是传统算法还是 AI？ 

A:

1. 分场景：明显、对比度高的划痕用传统算法（Blob、灰度差分、滤波增强）检测，速度快、可控性强。
2. 极微小、低对比度、和基材纹理接近的细微划痕，单纯传统算法容易大量误检，会搭配AI深度学习分割模型。
3. 整体方案：先用PMA定位电芯，裁剪ROI，传统算法预处理，再AI做缺陷分割，两者结合，兼顾节拍和检出率。

Q12：锂电池项目为什么两个月就能验收？

 A:

1. 上位机框架是之前项目沉淀成熟的框架，通信、日志、数据库、界面模块可以直接复用，不需要从零开发。
2. 前期售前评估充分，提前拿到客户样品，完成打光验证、算法可行性评估，识别项目风险，硬件提前选型备货。
3. 算法开发和硬件安装并行开发：机械机架、相机光源安装调试的同时，开发VisionPro算法脚本和上位机业务逻辑。
4. 分阶段交付：先完成算法离线验证，现场上机联调；小批量试产，迭代阈值优化，最后做稳定性测试，满足漏检误检指标后验收。
5. 客户配合度高，样件、NG/OK标准样件提供及时，缺陷判定标准提前对齐，减少后期反复修改。

Q13：键盘缺陷检测讲一下流程，检测精度是多少？ 

A:

1. 检测流程：
   1. 工件到位，光电触发相机拍照。
   2. PMA模板定位键盘基准位置，修正产品偏移与旋转，裁剪按键ROI区域。
   3. 图像预处理：滤波降噪，增强字符、边缘对比度。
   4. 算法检测：Blob、卡尺工具检测字符缺失、断字、划痕、脏污、键帽缺损、键帽高度异常。
   5. 结果判定：收集所有缺陷，对比阈值，输出OK/NG。
   6. 数据存储：检测结果、图像存入数据库，PLC接收NG信号做分拣。
2. 精度：像素当量约0.02mm/pixel，缺陷检测精度可达0.04mm。

## 10组

Q1：光源的安装角度是60°，拍摄的图像噪声比较多，要怎么调整光源？（不能图像处理）

 A:

1. 降低光源角度：把60°调低到30°~45°，减少表面反光带来的杂点噪声。
2. 调整光源高度：抬高或降低光源，改变入射光反射方向，避开镜面反射。
3. 更换光源类型：如果是反光工件，可更换环形低角度光源、增加偏振片，抑制镜面反光噪声。
4. 调光源亮度：降低光源强度，避免局部过曝产生噪点；不要过暗，否则信噪比下降。
5. 调整光源距离：改变光源与工件之间距离，均匀化打光，减少局部高光噪点。
6. 清理工件表面、光源镜头灰尘，避免灰尘造成伪缺陷噪声。

Q2：九点标定的作用是什么？

 A:

1. 建立图像像素坐标与世界物理坐标之间的仿射变换关系。
2. 实现像素坐标转机械坐标，得到像素当量，计算真实物理尺寸。
3. 修正镜头畸变、安装倾斜带来的坐标偏差。
4. 视觉检测得到的缺陷坐标、位置偏移，可以转换成机械坐标发给PLC或者运动控制器做纠偏。

Q3：旋转标定的作用是什么？

 A:

1. 九点标定默认假设工件只有平移，没有旋转；当工件发生旋转时，单纯九点标定坐标转换会出现误差。
2. 旋转标定采集工件多个旋转角度下的标定点，计算旋转带来的坐标偏移补偿。
3. 工件旋转后，依然可以把图像上的像素点准确换算到世界坐标系。
4. 多用于多相机坐标统一、工件旋转纠偏场景。

Q4：远心镜头和普通工业镜头的区别是什么，最关键的区别是什么

 A:

1. 普通镜头：存在透视畸变，工作距离变化，视野和放大倍率会跟着变化；近大远小。
2. 远心镜头：平行光入射，**物方放大倍率不随工作距离变化**，消除透视畸变。
3. 其他区别：远心镜头体积更大、价格更高；景深相对更小，对安装距离更敏感。
4. 最关键区别：远心镜头放大倍率不受工作距离影响，消除近大远小透视畸变，尺寸测量精度更高。

Q5：相机拍摄工件只能拍到30%，但想要看到工件的70%，怎么解决（不能图像拼接）

 A:

1. 更换焦距更小的镜头：同等工作距离下，短焦镜头视野更大。
2. 增大工作距离：相机镜头远离工件，扩大视野（需要确认现场空间允许）。
3. 更换靶面尺寸更大的相机：相同镜头、工作距离下，更大靶面视野更大。
4. 多相机同步采集：多台相机同时拍摄工件不同区域，统一世界坐标系，不做图像拼接，只统一缺陷坐标。

Q6：补偿值是怎么得到的 

A:

1. 通过VisionPro PMA模板匹配，算出工件相对于模板基准的像素偏移量、旋转角度。
2. 利用九点标定矩阵，把像素偏移转换成世界坐标系下的物理XY偏移与角度。
3. 这个物理偏移量，就是运动控制器/机器人需要移动的补偿值。
4. 下发补偿值给运动机构，机构移动消除工件位置偏差，完成视觉引导纠偏。

Q7：做过什么瑕疵检测

 A:

1. 锂电池电芯表面划痕、脏污、凹坑、掉料缺陷检测。
2. 键盘键帽字符缺损、划痕、脏污、键帽缺损检测。
3. 塑胶件外观崩边、缺料、溢胶、黑点缺陷。
4. 配合3D线扫做翘曲、高度差、平面度检测。
5. 项目中大多是传统算法为主，低对比度微小缺陷搭配AI辅助。

Q8：halcon了解吗 

A:

1. 了解Halcon，看过文档和基础算子，掌握基础思路。
2. Halcon算子非常丰富，图像预处理、测量、定位、3D算子齐全，灵活性强。
3. 对比VisionPro：Halcon偏代码式开发，适合复杂定制算法；VisionPro可视化工具链，调试更快，适合快速落地项目。
4. 项目主要使用VisionPro，Halcon做过学习与简单Demo，没有大规模产线项目。

Q9：visionPro里用过什么定位工具，用来干什么 

A:

1. CogPMAlignTool(PMA)：PatMax模板匹配，最常用。抵抗光照、轻微形变，实现工件定位，输出XY、角度偏移，用于缺陷检测前ROI定位、视觉引导纠偏。
2. CogFindCircleTool：找圆，用圆形特征定位基准。
3. CogFindLineTool：找线，以边缘直线做基准定位。
4. CogBlobTool：斑点分析，通过Blob特征重心做简单定位。

Q10：多线程是怎么使用的

 A:

1. 使用Task异步多线程，拆分任务：图像采集、算法运算、串口/TCP通信、数据库IO放在后台线程。
2. UI主线程只负责界面渲染，不做耗时运算。
3. 线程间共享变量使用lock做线程安全；使用委托/事件回调通知UI更新。
4. 使用信号量控制并发数量，防止瞬间多帧图像运算导致CPU打满。
5. 窗体关闭时，取消后台任务，释放资源，避免内存泄漏、程序崩溃。

Q11：有用过委托吗

 A:

1. 用过委托，项目经常用到。
2. 用途：跨线程更新UI图像、检测结果；作为回调函数，在图像采集完成、算法跑完后通知UI刷新。
3. 搭配事件使用，实现模块解耦，比如通信模块收到报文后触发委托回调给上层业务。
4. 使用Invoke/BeginInvoke实现跨线程UI操作，注意线程安全。

Q12：九点标定里的矩阵转换有了解吗

 A:

1. 九点标定得到**仿射变换矩阵CogAffineTransform**，是2D坐标转换。
2. 仿射变换包含平移、旋转、缩放、剪切，可以完成像素坐标 → 世界机械坐标正向转换，也可以反向世界坐标转像素坐标。
3. 公式：世界坐标点 = 仿射矩阵 × 像素坐标点。
4. 矩阵通过9组像素-机械对应点最小二乘拟合算出；用RMS残差评估矩阵精度。
5. 拿到矩阵后，可以调用图形对象Transform方法，直接对点、线、矩形做坐标映射。
